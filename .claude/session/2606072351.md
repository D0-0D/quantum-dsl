## OPEN ISSUE (blocker, NOT M3) — real Palace solve fails at mesh load
A live (non-`--dry-run`) Electrostatic solve **does not complete** through the geo
pipeline. Two distinct MFEM failures:
1. `chip_layout` → *"Invalid mesh topology. Interior triangular face found connecting
   elements … (3)"* — non-conformal face (coplanar overlapping metal/ground slabs).
2. clean `two_pads` → after *"Removed N unmarked domain elements"*,
   `GetFaceToBdrElementMap` verification fails (terminal boundary topology).

**Root cause:** conductors are extruded into thin **metal slabs**, fragmented against
substrate+vacuum, then **removed by Palace** (unmarked → no material), leaving invalid
boundary topology. The working PoC instead **subtracts** conductor solids from the
dielectric (`occ.cut`) so the domain is ONE volume with conductor-shaped cavities and
each terminal is a clean cavity-wall boundary. → The geo (and likely legacy) mesh
**conductor representation** must change to be Palace-solvable. **M1's "Palace
verified" was `--dry-run` only**, which never exercises full MFEM topology finalization.

This is upstream of M3 and affects the legacy path too. M3 write-back is code-complete
and will produce `chip.results.yaml` automatically once a real solve emits the CSVs.

## Research outcome — conductor-representation approaches (workflow `mesh-conductor-representation`)
**The invariant** (PoC + both MFEM errors): every Palace Terminal/Ground face MUST be an
**EXTERIOR** face of the meshed domain (≤1 adjacent element). `GetFaceToBdrElementMap`
rejects a boundary attribute on an interior (2-element) face.

- **A — occ.cut voids (mirror PoC). RECOMMENDED (9/10).** Carve conductor solids OUT of
  the substrate+vacuum domain → cavity walls are exterior faces → invariant satisfied.
  The only proven-correct path. `_sfs` name contract survives byte-identical IF a new
  `assign_physical_groups` branch re-emits cavity faces under the same
  `{C}_{P}_sfs` template (palace `_conductor_groups` matches on name suffix, not on a 3D
  volume existing). Effort **large**; **cannot** be localized to `populate_tracker_from_geo`
  (carve tools — vacuum+substrate — don't exist yet there). Needs a new shared stage
  `carve_conductors(tracker)` between `render_vacuum_box` and `fragment_everything`, plus
  GeomTracker `conductor_solids`/`conductor_faces` fields (+remap), `assign_physical_groups`
  branch, `_conductor_surface_tags` repoint. ~6 files. **Geo-path-only** (legacy YAML & GDS
  untouched — both confirmed decoupled).
- **B — zero-thickness embedded PEC surface (2/10).** Physically the MOST faithful thin-film
  model, but makes the terminal a 2-element INTERIOR face = exactly what MFEM rejects;
  also reintroduces the M1 embedded-surface meshing fragility. Won't work in Palace 0.16.
- **C — keep slab, add material / fix topology (3/10).** Dead end. c1 makes the mesh LOAD but
  leaves terminals on interior faces → either rejected OR a **silent wrong answer** (thickness/
  eps-dependent matrix written as `tier=3`). c2 only fixes chip_layout's non-manifold seam.

**Open questions to de-risk A with quick experiments before committing:** (1) cavity-wall
