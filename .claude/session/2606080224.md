## Migration decision (10-agent workflow: 3 understand → 3 design → 3 adversarial verify → synth)
- **Mechanism = `emit_geo(ir)` bridge** (the M5 "legacy bridge"): KEEP the whole v3 template engine
  (registry/expansion/expression/geometry_ops → `ComponentIR/PrimitiveIR/PinIR`, transmon_pocket.yaml
  verbatim) as the cell library; add a backend that lowers the resolved primitives → a flat
  positive-tone native `.geo` with `role::layer::comp::prim` names. Runs **upstream of `load_geo`**;
  nothing below load_geo changes (Palace names stay byte-identical / source-agnostic).
- **Rejected**: (A) re-author every cell as a Gmsh macro — feasible but loses v3
  expression/generator/merge_rule machinery; per-instance `Q1/Q2` name un-generatable in macro
  language; buffered-subtract fidelity lost. (C) full two-layer library+LUT subsystem — right
  architecture but very-large; phase it.
- **Adversarial finding (load-bearing)**: the naive emit_geo subtract model (difference subtracts
  against the *same component's* metals) is WRONG and contradicted by code — `apply_cuts`
  (`_gmsh_layers.py:254`) cuts per-LAYER from a ground sheet, and v3 has no ground primitive.
  **Fix**: synthesize ONE ground per layer, aggregate ALL `subtract:true` prims → punch as holes via
  a single OCC `BooleanDifference` (mirrors `GROUND_CUTOUT`).
