## 2. 复现命令 / 失败矩阵

```bash
conda activate metal-env; export PYTHONPATH=src QDSL_MESH_ALGO3D=10
python -m quantum_dsl.dsl.geo_build examples/dsl/geo/sung_2021_device.meta.yaml --out-dir <out>
# -> Exception: HXT 3D mesh failed / Found two exactly self-intersecting facets (#173,#174)
```
GDS 分支是好的（7 个 layer-1 多边形 = ground 553600 µm² + 6 焊盘；3 个 layer-20 JJ，面积/bbox 逐个核对无误）；
失败点在 `build_mesh_from_geo → generate_mesh`。

| 变体 | 结果 |
|---|---|
| algo3d = 默认(Delaunay→HXT 回退) / 10 / 1 / 4 / 7，min_size = 2 / 5 (/10) | 全 FAIL（默认路径：`3D mesh generation produced no elements`；HXT：`self-intersecting facets`；Delaunay：`overlapping facets on surface 173/174`） |
| `substrate_gap_um: 1`（默认 ε-nudge） | 拓扑变干净（2 体、6 个焊盘面全邻真空、无负面积），但仍 FAIL：`PLC Error: A vertex lies in a segment`，顶点 = pocket 角 (±385, ±120, 1 µm) |
| G2 去掉 2 条耦合 trench / G4 trench 端点内缩 / G5 ground 先建+显式高位 tag（照 qm4q 的构造要点） | 全 FAIL，报错与 G1 同 |
| G3 只留 QB1（1 pocket、2 焊盘、无 trench）；G3 + pkt_gap 50 / 100 | 全 FAIL |
| **对照 `qm4q_transmon_cell`（同 env、同命令）** | **OK**，10 个 physical group |
| **对照 qiskit-metal 自己的 QGmshRenderer 渲染同一版图** | **OK**，449765 tets（min5/max50, algorithm_3d=10） |

→ 同一份 2D 版图 qiskit-metal 的 gmsh 渲染器能顺利出网格；失败发生在我们的
「conductors-as-voids + carve + fragment(µm 往返 dilate)」这一段。**这是 Approach A 的几何相关脆弱性，不是版图问题。**

取证细节（`diag3.py`，substrate_gap 0）：
```
volumes: [(8, 1.2e+09um3), (9, 4.077e+09um3), (10, 1.2e+09um3)]   # 8 与 10 同体积 = 衬底被复制
surf 173 area=5.536e5um2 vols=[9]      grp=['gnd_layer1_sfs']     # 真 ground 腔壁, 正确
surf 231 area=-7.008e5um2 vols=[8,9]   grp=None                   # 负面积 = 损坏 face
surf 235 area=1.6005e6um2 vols=[8,10]  grp=['gnd_layer1_sfs']     # 整张 z=0 界面被误标为 ground
```
误标机制：`resolve_conductor_faces` 只做 `_centroid_in_bbox`；该巨型 face 质心 (0,0,0) 落在
chip-wide ground 的 bbox (−600,−300,0)–(600,300,2) 内 → 被 ground 认领。**没有面积/范围的一致性检查。**

## 3. qiskit-metal 侧重建 + Elmer 电容（用户要求的对照）

- 环境：conda `quantum-metal`（qiskit_metal **0.7.6**，editable 自 `~/metal/qiskit-metal`，gmsh 4.15.2）。

  `fem/src/modules/DCRComplexSolve.F90`（"Index variable 'i' redefined …"，与本任务无关的

  用 `export PATH=$HOME/opt/elmer/bin:$PATH`。
- 重建（`qm_sung.py`）：`designs.MultiPlanar` + 3×`TransmonPocket`（QB1/CPLR/QB2，pad/pocket/pad_gap/

  qiskit-metal 默认值，与 sung meta **完全一致**（layer1 pec 2µm@z0 + layer3 silicon −750µm）；
  外真空壁 = `Electric Infinity BC`(FarField) ↔ 我们的 `outer_boundary: open`。

- **qiskit-metal 的 `QElmerRenderer` 有两个坑（上游 bug，非本仓）**：
  1. `ElmerRunner.run_elmergrid` 假定 `cwd/out.msh` + `cwd/<simulation_dir>`；`simulation_dir`
     给绝对路径就 `FileNotFoundError: 'out'`。解法：`os.chdir(workdir)` + `simulation_dir="simdata"`。
  2. `_get_capacitance_matrix` 用 **pandas 链式赋值** `df2[i][i] = -s` 设 Maxwell 对角；
     pandas ≥2 copy-on-write（此机 **3.0.3**）下**静默失效** → 它返回的"Maxwell 矩阵"对角上留着
     `−c_i0`，而真正的 Maxwell 对角被放进了 `ground_plane` 行/列。**故本 review 从 Elmer 原始
     `cap_matrix.txt` 自行重建 Maxwell 矩阵。** Elmer 定义已按源码核实
     (`StatElecSolve.F90:509-519`)：打印的是**互容/SPICE** 矩阵（对角 = 对地电容、非对角 = 正的两体电容），
     且 sif 里 `Permittivity of Vacuum = 1` → 原始数值需 ×ε0。

  | g_1c / g_2c (MHz) | 102.8 / 110.1 | 72.5 / 71.5 | 1.42 / 1.54 |

  C_Σ / E_C / q–c 耦合都进了目标; **唯一未达标是直接 qubit–qubit 电容 C_12**(低 ~50×) ——
  780 µm 焊盘间距 + 中间 720 µm 的 coupler 岛, 差分-差分项是四个 ~0.19 fF 数的差; 要做到需要
  一条直接的 q–q 通道, 会破坏已标定好的 C_1c。已在 header 里如实写明, 未假装复现。
  g 偏高主因是**没有磁通轴**: 论文的 g 报在 ω_c/2π = 5.45 GHz, 本模型停在 coupler 零磁通 6.79 GHz。
  **陷阱记录**: circuit_model 报的 `g_12` (3.4 MHz) 与论文 5.0 MHz 接近是**巧合** —— 它来自
  `[C'⁻¹]₁₃`, 由 coupler 中介的 C_1c·C_2c 路径主导, 而非上面那个直接 C_12。
