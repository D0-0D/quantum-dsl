## 1. 缺口⑦ — `geo_build` 暴露 Palace 的 MPI rank 数

**问题**：`run_palace(config_path, *, dry_run, num_procs)` 早就支持 `num_procs`（native 走 `-np`，

  且在任何 mkdir/构建之前 → 失败不留半个 out_dir。

1. `run_palace` 两分支不一致（`palace_adapter.py:419-448`）：native 分支非 dry-run 时**无条件**

## 2. 缺口② — 磁通可调（可非对称）SQUID 的 E_J

**问题**：`JunctionInput` 只能给标量 `L_J` / `E_J`。真实可调 qubit 是 SQUID，且工艺上两结通常
不对称。复现 Sung et al. 2021 时 CPLR / QB2 都是非对称 SQUID，DSL 里只能填零磁通下的
E_JΣ —— **这是那次耦合 g 算高约 1.4× 的主因**。

**物理**（Koch et al. 2007, PRA 76, 042319）：

```
E_JΣ = E_J1 + E_J2      d = (E_J2 − E_J1)/(E_J1 + E_J2)
E_J,eff(Φ) = E_JΣ·|cos(πΦ/Φ0)|·sqrt(1 + d²tan²(πΦ/Φ0))
           ≡ E_JΣ·sqrt(cos²(πΦ/Φ0) + d²sin²(πΦ/Φ0))      ← 实现用这个
```

两式代数上恒等，但**教科书写法的 tan 在 Φ=0.5Φ0 处发散 → 0×∞ → nan**；无奇点形式处处有限，
实现为 `e_sum * math.hypot(cos(phase), asym * sin(phase))`（`hypot(1.0, 0.0)` 精确返回 1.0，
所以 flux=0 逐位退化成 E_JΣ）。d=0 时 Φ=0.5Φ0 精确归零；d≠0 时取极小值 E_JΣ·|d|。
纯 stdlib，`circuit_model.py` 的「不 import numpy/scipy」约束保持。

**DSL 表面**（`squid:` 子块，比在 `E_J` 上做多态类型干净）：

```yaml
circuit_model:
  qubits:
    - name: CPLR
      islands: [metal::1::CPLR::pad_top, metal::1::CPLR::pad_bot]
      squid: {E_J1: 60GHz, E_J2: 11GHz, flux: 0.0}   # flux 可省, 默认 0.0
```

`E_J1`/`E_J2` 走**同一个** `_parse_ej_joule`（没新写换算）；`flux` 是裸浮点 Φ/Φ0。
`L_J` / `E_J` / `squid` **三选一**。

**改动**：

| 文件                                   | 改动                                                                                                                                                           |
| -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `circuit_model.py`                   | 模块 docstring 加 Koch 2007 推导段（含「必须用无奇点形式」的理由）；`JunctionInput` 加 `E_J1`/`E_J2`/`flux`；三选一校验；`e_j_joule()` 加 SQUID 分支 |
| `schema.py`                          | `CIRCUIT_QUBIT_KEYS += "squid"`；新增 `CIRCUIT_SQUID_KEYS`（+`__all__`）                                                                                 |
| `parsers/simulation.py`              | `_parse_qubit_entry` 互斥→三选一；新增 `_parse_squid_entry()`                                                                                             |
| `geo_build.py`                       | 286-311：`JunctionInput(...)` 加 3 个 kwarg；provenance 三分支写 `squid: {E_J1_J, E_J2_J, flux_Phi0}`                                                      |
| `docs/report/04-geo-meta-grammar.md` | §4.6 补`squid:` 语法                                                                                                                                        |

**`palace_adapter.py` 没改**（判断：`QubitResult.E_J_GHz` 已是 flux 处的有效值，而
`chip.results.yaml` 同一个文件里 `provenance.circuit_model_inputs.qubits[].squid` 已如实登记
`E_J1_J`/`E_J2_J`/`flux_Phi0`，再加 `is_squid`/`E_J_sigma_GHz` 只是重复同一份信息）。

**边界**：`E_J1`/`E_J2` 必须有限且 >0；`flux` 必须有限；`flux` 配 `L_J`/`E_J` 直接报错

## 3. 顺手修的两个 bug（都是 subagent 报告、我实施）

### 3a. `L_J`/`E_J` 接受 nan/inf → 静默写出一整条 nan 的结果

`nan <= 0` 是 `False`，光判 `<= 0` 会放行；下游 `f01 <= 0` 对 nan 同样是 `False`，
**绕过** `non-transmon regime` 守卫 → `QubitResult(E_J_GHz=nan, f01_GHz=nan, EJ_over_EC=nan)`
无任何报错地写进 `chip.results.yaml`。属 #14 review 的 silent-wrong-result 一族。
**YAML 路径也能踩到**：`L_J: 1e400H` / `E_J: 1e400GHz` float 溢出成 inf 会一路通到结果文件
（`"nanH"`/`"infH"` 被单位正则挡住了，只有溢出这个口子）。

修法：4 处 `<= 0` → `not (math.isfinite(v) and v > 0)`（`circuit_model.py` 2 处 +
`parsers/simulation.py` 2 处，后者补 `import math`）。**消息前缀保留 `must be > 0`**
（改成 `must be > 0 and finite`），否则 `test_junction_input_rejects_empty_islands_and_nonpositive`
的 `match="L_J must be > 0"` 会挂 —— 第一版就是这么挂的。
测试：`test_junction_input_rejects_non_finite_l_j_and_e_j`（parametrize nan/inf）+
`test_circuit_block_rejects_overflowing_l_j_and_e_j`（YAML 层 1e400）。

### 3b. `test_geo_pipeline.py` 的 live-Palace gating marker 错位

`@pytest.mark.skipif(not QDSL_RUN_PALACE)` 挂在 `test_build_geo_archives_inputs_and_writes_manifest`
上（这个测试自己的 docstring 就写着「此处不跑 Palace」），而真正需要活 Palace 的
`test_two_pads_live_capacitance_matrix` **没有 gate**。marker 上移了一个函数。
**这就是 `status.md` 里那句「1 skipped + 必须手工 `--deselect` 活解测试」的来源。**
修法：把 section 注释 + marker 挪到 live 测试头上，manifest 测试给一个 `# build manifest (no Palace)` 的独立小标题。修完之后**跑全套不再需要任何 `--deselect`**。

## 7. ε-nudge 复查：那 ~30% 是**默认值选得太大**，不是挖空的内在代价

**起因**：用户质疑「挖空按理说不应该导致任何问题」。这个质疑是对的 —— 金属底面**就该**与衬底
顶面共面，那才是物理真相；ε 是纯粹的工具妥协。于是实测。

**先厘清适用面**（此前从未写清）：ε-nudge 只在 `tracker.ground_solids` 非空 **且** 该 dielectric
layer 走 **auto-substrate**（`.geo` 里没有 authored `substrate::` 面）时才触发。

- `two_pads`（活解回归的 24.73 fF）**没有 `ground::` 角色** → nudge 从不触发 → **那个数一直是
  物理精确的**（金属直接坐在 z=0 的衬底上）。
- `qm4q_transmon_cell` / `sung_2021_device` 都显式写 `substrate_gap_um: 0`，且都**没有** authored
  substrate → 走 auto-substrate 但 ε=0 → 也是物理精确的，**且确实能 fragment**。
- 真正吃默认值的只有 `chip_layout` 和测试 fixture（`tiny_chip`）。

**实测装置**：`scratchpad/eps/two_pads_gnd.geo` = `two_pads.geo` 原样 + 一张 500×500 带
320×160 挖孔的 `ground::1::chip::gnd`（两焊盘各留 40 µm 净空）。**唯一变量是 ε**，网格设置/
airbox/求解阶数全部不变，8-rank Palace 实解。

| ε (µm)      | C_AA (fF)                                                                                     | C_AB (fF) | vs ε=0.001                 |
| ------------- | --------------------------------------------------------------------------------------------- | --------- | --------------------------- |
| 0             | **`occ.fragment` 在 scale 1.0 与 100.0 全失败**                                       | —        | —                          |
| 0.001         | 26.2405                                                                                       | −1.6950  | 参考                        |
| 0.01          | 26.2325                                                                                       | −1.6943  | −0.03% / −0.04%           |
| 0.1           | 26.1500                                                                                       | −1.6854  | −0.35% / −0.56%           |
| 0.5           | **post-fragment 拓扑损坏**（2 体重叠，总体积 1.376× 模型 bbox）—— 被 A1 的不变量抓到 | —        | —                          |
| 1.0（旧默认） | 18.6077                                                                                       | −1.0117  | **−29.1% / −40.3%** |

三个结论：

1. **「~30%」得到独立复现**（−29.1%），而且**耦合比自电容更敏感**（−40.3%）—— 这一条此前没人量过。
2. 但它**完全是 1 µm 这个默认值比需要的大三个数量级**造成的。ε 从 0.1 → 0.01 → 0.001 单调平滑
   收敛，ε→0 的极限行为良好；1 µm 只是远在线性区之外。
3. **ε=0 不是万能解**：本几何在任何 coordinate scale 下都 fragment 失败。ε=0.5 更妙 —— 产出
   损坏拓扑，被 A1 那个不变量检查拦住（否则就是又一次静默错解）。所以 OCC 布尔在共面输入上的
   抽风是**非单调**的，没有「一律用 0」这个答案。

**改动**：`CARVED_GROUND_SUBSTRATE_GAP_SI` **1e-6 → 1e-8**（1 µm → 0.01 µm）。0.01 µm 距实测
可用区间两端各一个数量级，低于物理膜厚（100–200 nm），代价 0.03%。上面这张表连同理由写进了
常量旁的注释（含 `ponytail:` 标注：这是标定旋钮不是修好，真正的修法是缺口 ③
`mesh.conductor_mode: void|volume` —— 零厚度金属 `fragment` **进**界面，根本不需要共面布尔）。
`parsers/simulation.py:266` 那条说「默认是 1µm」的注释同步改掉。

**回归**：全套 `368 passed, 3 skipped`（不变）。关键覆盖是 `tiny_chip` —— 它**正是**老注释点名
会 mis-resolve 的「居中焊盘 + ground 环」，而套件里 `test_build_mesh_from_geo_physical_attributes`
与 `test_geo_group_names_match_geo_name_to_group` 都对它 `generate=True` 真出网格并断言组名
（`gnd_layer1_sfs` / `P_pad_sfs` / `substrate_layer3`），在 ε=0.01 µm 下依旧全对 → 新默认值
没有把 `resolve_conductor_faces` 推回误配。另单独确认 `chip_layout`（唯一吃默认值的例子）
在新默认下仍能完整构建。
