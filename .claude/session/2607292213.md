## 2. Review findings（按严重度）

### 🔴 F1 — `from: file` 读 Palace CSV 时终端名自动生成 `t1..tN`, 两个块会**静默合并**

`capacitance_from_file()` 在 Palace CSV 上拿不到终端名 → `_bind_terminals(None, n)` 生成
`t1..tN`; `geo_build` 调它时**不传** `terminals=`, schema 的 `EXTRACT_BLOCK_KEYS` 也没有
`terminals` 键。于是两个 `from: file` 的 Palace-CSV 块拿到**同一组**节点名, `assemble` 按
「共享节点名」把它们**当成同一批导体累加**。实测:

```
两份相同的 2×2 CSV（对角 20/30 fF）→ assembled nodes ('t1','t2'), maxwell 对角 40/60 fF
audit.shared_nodes = ['t1','t2'],  warnings = []      ← 没有任何警告
```

R2 的警告只对「共享且**没有**结引用」的节点触发, 这里两块的结都引用它们 → 静默。
若两块都声明 transmon, `solve_circuit_model` 会以「两个岛是同一个 Terminal」偶然拦住（消息误导）;
但只要有一块是被动件（读文件的谐振器爪子矩阵 / 耦合器）就**完全静默出货**。
P0-C 明确定位为「主流程不是旁路」, 所以这条要修。
最省的修法: `_bind_terminals` 的默认名带块标签（`geo_build` 把 `label=bname` 传下去 →
`qb1_t1`）, 或 `assemble` 对「两个 cell 共享节点、但双方都没通过 `nodes:` 显式命名过它」直接 raise。

### 🟡 F2 — 块窗口（S3）与 airbox（S4）复用**同一个** `airbox.side_buffer`, 且**叠加**

`geo_build.py`: `side_buffer_um = sim_gmsh["airbox"]["side_buffer"]` → 喂 `emit_block_geo` 当
块窗口余量; 而块 mesh 的 airbox 又是 `compute_chip_bbox_from_geo(块 metal+ground) + side_buffer`。
ground 被裁到窗口后就是块内最大的 `ground` 面 ⇒ **airbox = 窗口 + side_buffer = 金属 bbox + 2×side_buffer**。
后果两条:

- 调 airbox 的 padding 会**静默改动块的 ground/衬底外延**, 也就是改动电容。两个物理含义
  不同的距离绑在一个键上, 违反「几何参数的真值源可归档、可 diff」的精神（G2 的字面没破,
  因为它仍在 `meta.yaml` 里, 但可调性坏了）。
- `sung` 的分块 A/B 对照里, 块的真空外延是 `金属+400 µm`, 整片是 `ground 全片+200 µm` ——
  **不是同一个电学环境**。`two_pads` 不受影响（该 `.geo` 没有 `ground::`/`substrate::` 面,
  pass 2 空转）, 所以 **+1.03% 那个受控对照仍然成立**; 但 `2607290329.md` 里
  「同 airbox, 唯一变量是分不分块」这句对 sung 不准确。
  建议: 给 `extract:` 一个自己的 `side_buffer`（默认沿用 airbox 的值以保持现有数字不动）。

### 🟡 F3 — `assemble.ground_node` 写错名字是**静默 no-op**

参考地通常是 `ground::` 面, 它本就不是 Terminal, 所以 `resolve_all.get(name, name)` 原样透传、
`assemble` 里也永远匹配不上任何 terminal —— 这是**设计如此**（例子里有注释）。代价: 拼错
`ground_node` 与写对它**行为完全相同**, 没有任何提示。当 `ground_node` 本该指一个真的
`metal::` terminal（比如显式接地电极）时, 拼错会让它留在矩阵里被 Schur 消掉而不是接地 →
物理不同、无警告。最省的修法: `ground_node` 解析不到任何 terminal 时打一行 note
（「按『不在矩阵里的参考地』处理」）, 让作者能看见自己写的名字没被用上。

### 🟡 F4 — `nodes:` 键写错时的报错消息在 file/inline 块上给出**错的可寻址列表**

`_cell_from_block` 的 `known` 只来自 `aliases`（几何反查表）, 而 file/inline 块的 `aliases` 是 `{}`
→ 消息变成 `Addressable terminals: <none>`, 而实际上 `cap.terminals` 里有真名字。
一行修: `known` 兜底用 `[b.group for b in cap.terminals]`。

### 🟢 F5 — 一个块内两个 terminal 被 rename 成同名时的合并公式差一项 `C_ij`

`assemble` 的累加走上三角 `mat[r][c] += maxwell[i][j]`, 当 `i≠j` 但映射到同一节点时
`r==c`, 于是只加了**一次** `C_ij`, 正确的短接应是 `C_ii + C_jj + 2·C_ij`。
实际影响为零 —— `_cell_from_block` 已经**明确 raise**「块内两个 terminal 撞名」（注释也写了
「共享名只用于跨块」）, 所以这条路走不到; 且上游 `_adj_list_to_mat` 有同样的行为。
记下来是免得将来放开块内合并时踩到。

### 🟢 F6 — qubit↔谐振器的 `g`: 电容用**加载后**的、频率用**裸**的

`g = ½·|[C'⁻¹]_qr|/√([C'⁻¹]_qq[C'⁻¹]_rr)·√(f01·f_res)` 里 `[C'⁻¹]_rr = 1/C_r,eff`（含爪子加载）,
而 `f_res` 是裸频率。老 LOM 是（裸 C, 裸 ω）成对, 我们是（加载 C, 裸 ω）混搭 ——
自洽的配法应是 (f_loaded, C_r,eff) 或 (f_bare, C_r)。偏差是爪子加载量的一阶小量,
而且已经被「χ 对老 LOM −16.1% = g 定义 −8.5% × 谱 −8.3%」那笔分解在数值上吸收掉了
（乘积 0.8388 对实测 0.8392）。docstring 已声明取裸频率的理由, 保留即可, 但值得知道这不是
参考实现的同一约定。

### 🟢 F7 — gmsh model 只增不删

`load_geo` 每次 `gmsh.model.add(f"geo_source_{n}")`, 全程没有 `gmsh.model.remove()`。
分块路径下一次 build 里活着的 model 数 = 1（源反查）+ N（`emit_block_geo`）+ N（块 mesh）。
sung 3 块 = 7 份几何常驻内存。当前规模无害, 但块数上去（或 P2-J 扫参）就会显出来。

### 🟢 F8 — `units:` 在 Palace CSV 来源上被**静默忽略**

`capacitance_from_file` 对 Palace CSV 一律按表头（缺表头则按 `F`）换算, 刻意不看 `units=`
（理由正当: 缺省 `fF` 会把一张 F 矩阵缩掉 1e15 倍, docstring 写了）。但 sidecar 作者写
`units: pF` 不会有任何提示。低危, 提一句。
