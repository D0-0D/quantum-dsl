# 2608270333 — todo2 分析: "CPW 解析式 ↔ 脚本生成 CPW", .geo 语法够不够

用户问: geo 语法是否已能画 直线+圆弧 的 CPW 模板, 再配一个"画定长 CPW + 实时渲染"的辅助? 本会话只分析, 未改仓库代码。

## 实测 (scratchpad/cpwtest, 未进仓)
- 直—90°弧—直—弧—直 五段 CPW: `SEG`/`ARC` 宏(OCC `Circle` 扇环面) + `cpw_len` 在 .geo 里累加;
  完整 `build(solve=False)` 通过(GDS+msh+config, 双解析); Python 侧 `gmsh.parser.getNumber("cpw_len")` = 394.248 = 300+30π ✓。
- `BooleanUnion` 不把 Plane Surface 段 fuse 成单面(5 面, 与 qlib COUPLER 注记一致) → 一个 Physical 挂多面即可, mesh/GDS 都吃得下。
- **新坑**: 顶层 .geo 里放 `If(!Exists(_X))` 守卫的 Macro, 第二次解析报 "Input in flex scanner failed"; 同样内容放进
  `Include` 的库文件(qlib 写法)则双解析正常。规则: 宏只能住 Include 库。
- **GDS 圆弧缺口**: `gds.py` 固定 `Mesh.MeshSizeFromCurvature=0` → 90° 弧只 2 段折线(面积 +0.28%, PNG 肉眼可见);
  设 90 → −0.019%, 180 → −0.005%。引入弧后必须补(一行)。
- `gmsh.fltk.isAvailable()` = 0(本机 WSLg 下 GUI 不可用; 且在主进程里探测它会 segfault 整个进程, 要探测就开子进程)。
- .geo 数学函数 `Atan2/Hypot/Fmod/Abs/Cos/Sin/Sqrt/Pi` 齐全 → 折线自动倒角路由宏可纯 .geo 写。

## 结论(答复用户)
语法够, 库缺: qlib 加 `CPW_SEG/CPW_ARC/CPW_ROUTE(折线+半径)/MEANDER(定总长解尾段)`, 同路径宽 s 与 s+2w 各调一次 = 中心导体 + 地缝;
"实时辅助" = `Printf(cpw_len)` + build_gds→tools/gds_png.py 的 mtime 轮询, 不做交互画板;
闭环 = meta `subsystems:` 消费: `guided_wavelength()` 算目标长 vs `parser.getNumber(length_var)` 画出长, 报偏差(= #23 targets 在长度上的实例)。
不做: Python 生成 .geo 文本的 CPW 生成器(双语言重复)、把椭圆积分搬进 .geo。
