## 1. 一句话：这次做了什么

v4.0 只能吃**一整份手写 `.geo`**。这一阶段给它加了一层：**版图文件** `*.layout.yaml` 按顺序放置模板实例（整只 qubit、
耦合器、焊盘）、把端口连起来、再混入手写 `.geo` 补画，编译成同一个 gmsh 模型；下游 GDS / 网格 / Palace / 电路模型**一行未改**。
第一批模板是 Chen 2025 的圆盘比特（`disc_transmon`）与条形耦合器（`bar_coupler`），用它排出 3×3 阵列和十字，上云把
42 导体 / 18 导体一次解出来，对论文的三层参考值（实测 α、设计值、SI 电容表）逐项算账。

## 2. 为什么要版图编排，为什么长这样

| 问题 | 处境 | 做法 |
|---|---|---|
| **封装单位** | `qlib.geo` 宏只能封装焊盘一级；用户要的是封装**整只 qubit**（岛 + 结 + 爪 + 端口 + 层） | 模板 = **局部坐标 `.geo`（几何，不打名）+ 同名 YAML 接口**（参数默认值 / 岛 / 外挂面 / 蚀刻 / 结 / 端口 / 层槽位）。与项目本身「几何 + sidecar」两层结构同构，可嵌套 |
| **`.geo` 语法边界** | gmsh `.geo` 宏无参数、变量全局；曾评估 fork gmsh 给宏加参数与作用域 | 不 fork（bison 直译无 AST，3–4 人周只能做语句级；永久私有构建链）。编排器在 **Python 侧**做参数注入 / 差集变换 / 输出读取，`.geo` 只管画 |
| **与手写 `.geo` 的关系** | 用户要求：库不能与「正常写 `.geo`」割裂；模板跨层时想在某层再补几条线 | 手写 `.geo` 是版图的一种**步骤**（`geo:`），可挂在某实例的局部坐标下（`frame:`）、可声明端口、可认领模板画的外挂面（`connect:`）；**只增不改**（不 Delete、不对模板面做布尔） |
| **层** | 模板的层 1/2/3 与芯片的层 a..e 怎么对应，层性质谁定 | 层是模板的**局部命名空间**，实例化时按 `layers: {slot: chip_layer}` 重定位；层性质（kind / GDS 图层）由 meta 的 `layers:` 表决定，模板只声明槽位 kind 要求 |
| **路由** | CPW 不该从坐标出发，该从 pad / qubit 已给出的端面出发；爪形状奇特，等效长度由 qubit 模板给 | 端口 = 端面中点 + 外法向 + 宽 + 层 + 等效长度；路由只接端口、宽度继承；**路由是电连接**：路由体 + 两端外挂面并成一个 net |

设计稿 [`../design/component-library.md`](../design/component-library.md)（v3.1，三轮推翻重写后的框架稿，落地偏差已注）。

## 3. 架构增量

### 3.1 数据流：多了一个几何源

```
 *.layout.yaml ──► compile_layout ──► Layout (可调用几何源: 模板实例 + 手写步骤 + 路由 → 一个 gmsh 模型)
 (有序步骤)          │  同时产出: circuit_model.qubits (结)  subsystems (谐振器长度)  ports  inputs (manifest 用)
 *.meta.yaml ───────┤
 (+ layers: 层表)    ├──► build_gds  ──► *.gds (+ *.gds.png)                 ① 与 v4.0 相同
                    ├──► build_mesh ──► *.msh ──► palace_config ──► *.json  ②③ 与 v4.0 相同
                    │        blocks=[…]: for_block() 过滤 → block_<name>.msh/.json (跳过整片)
                    └──► solve=True ──► Palace ──► parse_capacitance ──► solve_circuit_model ──► results.yaml
 手写 *.geo ─────── (v4.0 路线原样保留: meta 写 geo: 而不是 layout:)
```

### 3.3 绑定键不变，多一条规则

Physical 名 `role::layer::component::primitive` 的 component 段仍是电学岛。编排器按实例名生成：单岛模板 `<实例>`，多岛
`<实例>_<岛键>`，嵌套加父前缀；**连接型模板的路由体 component 就是 net 名**（恰一个岛端 → 该岛名；零岛端 → 步骤名；两岛端 → raise）。
例：`bar_coupler` 步骤 `H01` 连两只爪 → 条 + 两爪 = `H01`，五边形 = `H01_pent`，结条目 `islands: [H01, H01_pent]` 自动生成。

## 4. 能力逐项

### 4.1 模板与版图
- 三种步骤：`template`（放置 `at / rot / mirror`，或连接 `from / to`）、`geo`（手写，`frame:` / `ports:` / `etch:` / `connect:`）、`route`（连接型别名）。
- 模板 YAML：`params` 默认值、`layers` 槽位、`islands`、`external`（可选外挂面，`if:` 守卫）、`etch`、`junction`、`ports`、`outputs`、`steps`（嵌套 + 再导出）。
- 编排器每步：把参数与此前实例的端口变量放进 gmsh 解析器 → merge `.geo` → 差集变换 → 读输出变量 → 按实例名挂名。**输出变量 NaN 置毒**：模板漏赋值不会读到上一实例的旧值。
- `ground: sheet` 在所有步骤后建大矩形并一次减去全部蚀刻工具面；`ground: none` 给 flip-chip。

### 4.2 路由 = 电连接（三种写法）
| 写法 | 适用 | 状态 |
|---|---|---|
| 连接型模板（`cpw_meander` / `bar_coupler`） | 两口**正对同轴**、同宽同层；局部坐标原点在 from 口、+x 指向 to 口，注入 `D / w / L` | 2026-09-12 |
| 手写 `.geo` + `connect: {net: [端口…]}` | 任意形状；认领模板画的外挂面（爪），与连接型走同一条 `_connect` | 2026-09-16 |
| **自动布线 `cpw_route`**（`planner: cpw`） | 两口**不必正对**，只需同宽；给目标长度（`length:`，减两端等效长度）、可用矩形区域（`region:`）、最小弯半径 `R` → Dubins CSC 四型 + 中段直段换蛇形；规划在芯片坐标，Python 只注入原语列表，`.geo` 用 `LIB_CPW` / `LIB_CPW_ARC` 画 | 2026-09-18 |

三种写法共用一条纪律：路由体必须真碰到每一端（`getDistance ≤ 1e-6`），隔着缝 raise；每个端口只能连一次；不同 net 同层相接 = 短路 raise。
`cpw_route` 在两口正对共线时与 `cpw_meander` 逐段相同（测试锚）。

### 4.3 Chen 2025 模板与例子
- `disc_transmon`：两半盘（缝 70 µm 沿 −45°）+ 盘心跨缝结 + 四只可选爪（外挂面 E/N/W/S，颈外端是端口）。`bar_coupler`：连接型，条 + 五边形 + 条–板结，两端爪并入条的 net；纵向写 `mirror: x`。
- 例子：`chen_2025_3x3`（9 + 12 步，21 结，87 Physical，编译 0.7 s / GDS 1 s）；`chen_2025_3x3_hand`（12 条耦合器换成一步手写 `.geo` + `connect:`，Physical 名 / GDS 多边形 / 结 / 端口逐点相同）；`chen_2025_cross`（中心比特四爪 + 四臂各一爪 + 4 耦合器 = 18 导体，整片一次解）。
- 几何全部是从论文 Fig. 1a 照片量出的（[`../design/paper-chen2025-geometry.md`](../design/paper-chen2025-geometry.md)），载片地 = `airbox.top_um = d`。

### 4.4 分块与整片求解
- `build(meta, out, solve=True, blocks=["H01"])` 只做指定块（本机 8 rank 约 10 min）；不带 `blocks=` 走整片。
- 上云跑法：本机出网格 + config → 推到有 spack Palace 的 64 核 / 128 G 机 → `palace -np N` → 拉回 `postpro/` → 同一套 `parse_capacitance` + `solve_circuit_model`。产品代码不感知远端。

### 4.5 拒绝静默：本阶段堵掉的路径（全部改 raise，各有回归测试）
| 类别 | 曾静默通过并产出错结果的路径 |
|---|---|
| 连接 | 连接型模板声明 `ports:` 时局部 `net` 遮蔽路由体 net；`mirror: y` 把路画向 to 口反方向；连接型吞掉 `at:` / `rot:`；外挂端口背后零个面时"连"到没画的金属；路由体没碰到端口那一端仍记进 net；同一表里重复端口报错文不对题 |
| 模板 | `port(i)` 简写没被 NaN 置毒（读到上一实例坐标）；`if:` 指向未声明参数 = 静默关闭；子字典键不查（`iff:` 丢守卫）；`body` 真值判断伪造岛键；`0` 岛键被判假；`Include` 的宏库不进 manifest；模板缺 `.geo` 的报错路径自己崩 |
| 手写步骤 | 模板步骤写 `frame:` / `connect:` 被吞；`layers:` 拼错的蚀刻面被地静默丢弃；merge 的文件里定义 `Macro`（文件关闭后宏体失效，同进程第二次跑段错误） |
| 分块 | 手写 Physical 组逐组删留残名 → 出网格 heap 崩溃；块集合重叠不告警（`assemble()` 会重复计入自电容） |
| 宏库 | 宏名 `CPW` 与用户 `qlib.geo` 重名 → "Redefinition of function" 炸整个 session；裸名入参活到后续手写步骤 |

## 6. 本阶段的决策记录

| 决策 | 结论 |
|---|---|
| 库的封装单位 | 模板（整只 qubit），不是 `.geo` 宏；`qlib.geo` 是用户文件，不搬不冻结 |
| 几何引擎 | 不 fork gmsh；不用 Python 发射 `.geo` 文本；模板默认形态 = `.geo` + yaml，Python 函数模板未做 |
| 手写 `.geo` 与模板面 | **只增不改**（布尔替换实体会让登记的 tag 失效、分裂面被网格静默删） |
| 爪的归属 | 由比特模板画（与盘共形），电学归接上来的耦合器 net；无邻居方向 `claw_*: 0`，画了没人连 → raise |
| 「两口正对」 | 是 8/27 工作树的端点约束（"cpw 起始角必须是 pad 的面"），不是算法能力。处置：直线保留正对；不正对用 `cpw_route` 或手写 |
| 契约编号 Nxx | 2026-09-17 全部清除（38 文件），SPEC 条目按名字引用；v4.0 收口时是有意保留的，不是遗漏 |
| Chen 验证的锚 | 用**实测 α** 定 d，其余（g、SI 电容）作预测；用 C04 定 d 的方案作废（SI 电容与我们互差 ×0.35–1.7，不是干净的锚） |

## 7. 当前边界与后续（诚实清单）

- **自动布线三处待拍板**：自动腿数取「能装进区域的最小 n」（稀疏大振幅）还是最大 n（紧凑），一行改；pad↔pad 缺两岛端 net 命名规则（demo 用 xmon 桨 → pad）；只做 CSC，两口距 < 4R 时不保证最短。多边形区域 / 避障 / taper 未做。
- **`cpw_meander` 退不退役**：它已是 `cpw_route` 的退化情形，但退化测试拿它当锚；方向 1「连接型收窄为直线」的其余项因 `LIB_CPW_ARC` / `length:` 有了消费者而失效。
- **Chen 互容缺口未解**：半盘–半盘 / 半盘–条 / 条–板互容恒为 SI 的 0.35–0.5 倍，对 d 与环境不敏感，是缝 70 / 间隙 12 / 缝 75 这些照片 ±30–50% 量的账；gap ±3 µm 灵敏度未做。g_qc / g_qq 系统性偏低由此而来。
- **d 的两个锚拉向相反方向**：命中实测 α 要 d = 4.0，对上 SI 电容表要 d ≈ 6–7，同工艺外部实测 5 ± 0.4；SI 自己的电容表推出的 E_C（209）与实测（192）也不闭合。
- **未画读出结构**（爪 225° / 焊盘 / λ/4）：估 C_Σ +3%，方向已知。
- `frame:` 步骤无测试、`readout_pad.geo` demo 未落仓；`.claude/*-evidence/` 迁 `v4-dev` 待做。
- 无 CI、无 CLI 不变。
