# quantum_dsl 工作汇报

> **本阶段成果**：芯片版图可以**画出带圆角的多边形**，跑**静电学求出电容矩阵**，再换算成**量子比特哈密顿量**
> （频率 / 非谐 / 耦合）；几何既能手写，也能只列几个组件**自动生成**。整条链路端到端打通并在本机实测。

## 1. 一句话：这是什么、这次做了什么

`quantum_dsl` 是一套面向 **超导量子芯片版图** 的 DSL（领域专用语言）。它把一颗芯片拆成**两层描述**
（几何 + 物理参数），一条命令同时产出 **流片版图（GDS）** 和 **静电仿真网格**，跑 **Palace** 解出
**电容矩阵**，再转成**量子比特哈密顿量**。

这一阶段的核心，是把项目从**早期的「YAML → qiskit-metal QDesign / 通用网格」形态**，重构成
**「原生几何 `.geo` → GDS + 静电电容求解」的主线**，并把「真正跑出电容矩阵 → 电路模型」这件**之前只停留在
计划里**的事做实。下一节先讲这次重构的取舍。

---

## 2. 重构：为什么从「YAML→QDesign/网格」转向「原生 .geo → GDS + 静电求解」

> 参照重构前的演示稿 [`dslv3_gmsh_presentation.html`](dslv3_gmsh_presentation.html)（"Qiskit Metal DSL v3"）。

### 2.1 重构前（DSL v3）

- **输入**：一份 `.metal.yaml`，把芯片的逻辑（hamiltonian/circuit/netlist）+ 物理布局（geometry）+ 仿真元数据
  （simulation）全写在一个文件里；`build_ir` 是唯一入口，产出纯 dataclass 的 `DesignIR`。
- **两条出口**：
  - 左路 `build_design()` → qiskit-metal **QDesign**（→ GUI / GDS / EPR）；
  - 右路 `build_mesh()` → 经一条 **7 段 OCC 渲染流水线**（render → tracker → endcap/port → ground/vacuum →
    symmetry-cut → cut → fragment → physical-group → mesh）把 YAML 几何生成网格 `.msh`，交给 Elmer / palace / HFSS。
- **当时状态**：网格能产出、命名契约已立，但「**真正接求解器跑电容矩阵、把 C 矩阵回算成哈密顿量**」
  在那版演示里还是**候选项（列为后续工作）**，没做。几何长在 qiskit-metal 仓库里（需要 QDesign 全栈），单位是 mm。

### 2.2 重构后（本项目 quantum_dsl）

- **输入拆成两层**：几何写在**原生 Gmsh `.geo`**（OpenCASCADE 内核，微米）；物理参数（材料/eps_r/网格/层映射/求解器）
  写在独立的 **`*.meta.yaml` sidecar**。几何**也可以不手写**——在 sidecar 里列组件实例（`cells:`），系统自动生成带圆角的 `.geo`。
- **两路产物**：**gdstk → `chip.gds`**（直接 2D，绕过网格）+ **Gmsh → `chip.msh` → Palace（Electrostatic）→
  电容矩阵 → 电路模型 → `chip.results.yaml`**。
- **把候选做实**：Palace 静电真求解（实测 `two_pads` 的 C 矩阵），并用逆电容法把 C 矩阵换算成 transmon 哈密顿量；
  加入 GDSFactory 版图可视化。

### 2.3 重构前后对比

| 维度 | 重构前（DSL v3） | 重构后（quantum_dsl） |
|---|---|---|
| 几何来源 | `.metal.yaml`（YAML）→ 7 段 OCC 渲染生成 | **手写原生 `.geo`**；或 `cells:` 块**自动生成带圆角** |
| 物理参数 | 混在 YAML 的 `simulation` 段 | 拆出独立 `*.meta.yaml` sidecar |
| 出口 | 左：QDesign（GUI/GDS）；右：通用 `.msh`（Elmer/palace/HFSS，**未真正接**） | `chip.gds` + Gmsh `.msh` → **Palace 真求电容** |
| 电容/电路 | **候选、未做** | **真实 C 矩阵 + transmon 哈密顿量（已做）** |
| 长度单位 | mm float | µm（GDS 原样；网格 µm→m） |
| 依赖 | 内嵌 qiskit-metal，需 QDesign 全栈 | 独立包，`gmsh/gdstk/gdsfactory` 懒加载，`import quantum_dsl` 干净 |
| 导体表示 | ground 切 slab | **导体即空腔**（满足 Palace 外边界不变量） |
| 模板引擎 | 直接喂 QDesign | **复用**，但 lower 成扁平 `.geo`（`emit_geo` 桥） |
| 命名契约 | `PHYSICAL_GROUP_NAMING` | **逐字节保留**，下游求解器无感 |
| 可视化 | Metal GUI | **GDSFactory** + matplotlib 回退 |

### 2.4 关键选择（为什么这么改）

1. **解耦几何与重栈**：旧路要 QDesign / QGmshRenderer / LayerStackHandler 全栈才能出几何。直接写 `.geo`
   把几何从这套重依赖里解放出来——`import quantum_dsl` 不拉 gmsh/gdstk/gdsfactory（懒加载），没装 GUI 的环境也能出产物。
2. **几何表达更直接、先收敛到主线**：本阶段目标是「带圆角多边形 + 静电电容」。原生 `.geo`（OCC 布尔/extrude）
   比「YAML→shapely→7 段渲染」更直接可控；endcap / port-surface / symmetry-cut 这些对**静电电容**不是必需的复杂度，
   先砍掉、把链路收敛到「电容矩阵」这条主干（电磁/端口等留待后续阶段，且是纯增量）。
3. **把候选做实、闭环到物理结果**：旧 deck 把「接 Palace 跑电容」列为候选；重构把它真正打通——用**导体即空腔**
   解决 Palace 的外边界要求，跑出 C 矩阵，再用逆电容法回算哈密顿量。
4. **不浪费已有的模板引擎**：旧版那套丰富的组件模板（继承链、参数化、圆角）没有扔掉——`emit_geo` 把
   `build_ir` 的解析结果**lower 成扁平 `.geo`**，模板能力完整保留，只是换了下游消费方。
5. **保住下游契约**：物理组命名规范**逐字节不变**，Palace 对几何来源无感。所以这次重构是「**加一条更短、更聚焦的主线**」，
   不是推倒重来——旧的 YAML 路径作为 legacy 仍保留，且其 `build_ir` 被新主线复用。

## 3. 整体架构

### 3.1 数据流：两层输入 → 两路输出

```
                          ┌─ gdstk ──────────────→ chip.gds ──(可选)→ PNG 预览（GDSFactory / matplotlib）
 Layer-1  *.meta.yaml ──┐ │
 (物理: 材料/eps_r/网格 ├─┤  共享 physical-group 模型
  /层映射/求解器)        │ │
 Layer-2  *.geo ────────┘ └─ Gmsh → chip.msh → Palace(Electrostatic)
 (几何, 微米 µm)                              └→ 电容矩阵 C → 电路模型 → chip.results.yaml
```

### 3.2 指令入口与调用链：一条命令 `build_geo` 串起全程

整条链路只有**一个入口**：CLI `python -m quantum_dsl.dsl.geo_build`，它解析参数后调用**唯一的编排函数
`build_geo()`**（`geo_build.py:55-267`）。所有具体活儿都由它**按固定顺序**调用各个适配器完成——适配器之间**互不调用**，
全靠 `build_geo` 串起来。一条命令展开成下面这条链：

```
$ python -m quantum_dsl.dsl.geo_build  chip.meta.yaml  --out-dir build/  [--run-palace] [--png]
      │   CLI: geo_build.main() 解析参数（argparse）           geo_build.py:274
      ▼
build_geo(meta_path, out_dir, run_palace, dry_run)         ← 唯一编排者   geo_build.py:55
  │
  ├ ① 解析 sidecar ........ parse_geo_meta_sidecar()   parsers/simulation.py   → meta dict（物理/层/求解器/cells）
  │
  ├ ② 定几何源（三选一，优先级从高到低）                                     geo_build.py:110-129
  │     · 显式 --geo 路径
  │     · meta 里有 cells: → elaborate_cells()   geo_emit.py:445  → 写 build/<stem>.elaborated.geo（自动生成带圆角）
  │     · 否则用 sidecar 里的 geo: 字段
  │
  ├ ③ 开 1 个 gmsh 会话（故意贯穿下面两路，见 §3.3 注）                       geo_build.py:150-154
  │
  ├ ④ GDS 路 ............. build_gds()                gds_adapter.py:144   → build/chip.gds
  │       └ load_geo(µm 直读) → surface_outline_um → gdstk.Library(unit=1e-6)
  │
  ├ ⑤ 网格路 ............. build_mesh_from_geo()      gmsh_adapter.py:550  → build/chip.msh
  │       └ load_geo(µm→m) → populate_tracker(按厚度 extrude；去掉 JJ) → render_vacuum_box
  │         → carve_conductors(导体即空腔) → fragment → resolve_conductor_faces
  │         → assign_physical_groups(统一命名) → define_size_fields → generate(3) → write
  │       产出 physical_groups + physical_attributes（下游 Palace 的引用键）
  │
  ├ ⑥ Palace 配置 ........ build_palace_config → validate_config → write_palace_config   palace_adapter.py:182  → build/chip.json
  │
  ├ ⑦（仅 --run-palace）... run_palace(dry_run?)        palace_adapter.py:394
  │       └ 非 dry-run: terminal_bindings → parse_capacitance_matrix → C 矩阵
  │         └（sidecar 有 circuit_model:）solve_circuit_model()   circuit_model.py:218
  │         └ write_results_sidecar()                                                    → build/chip.results.yaml
  │
  └ ⑧（仅 --png, CLI 层）.. preview_gds()              gds_viz.py:203       → build/chip.png
```

> 读法：**竖线左侧是 `build_geo` 的步骤，箭头右侧是产物文件**；`模块.py:行号` 是该步真正干活的函数所在。
> ④⑤ 是「一份输入两路产物」的分叉点，⑦⑧ 是可选项（不给 `--run-palace` 就只出 GDS+网格+配置，不求解）。

### 3.3 模块依赖关系：一个编排者 + 一组叶子适配器 + 共享地基

代码分三层，依赖**单向向下**（上层调下层，**同层不互调**）：

| 层 | 模块 | 职责 |
|---|---|---|
| **编排层** | `geo_build.py`（`build_geo` + CLI `main`） | 唯一入口；按 §3.2 顺序驱动下面所有适配器。CLI 只解析参数 |
| **叶子适配器**（各管一件事，彼此独立） | `geo_emit`（cells→`.geo`）· `gds_adapter`（GDS）· `gmsh_adapter`（网格）· `palace_adapter`（配置/求解/解析/写回）· `circuit_model`（C→哈密顿量）· `gds_viz`（预览） | 每个适配器只被 `build_geo` 调用，**不调用彼此** |
| **共享地基**（被多个适配器复用） | `_gmsh_geo_source.load_geo`（`.geo` 摄入，GDS 路与网格路**同一个入口**）· `_gmsh_physical`（`PHYSICAL_GROUP_NAMING`/命名）· `_gmsh_layers`（挖空/归位）· `_gmsh_mesh`（尺寸场）· `schema`（role/绑定 key 常量）· `parsers/simulation`（sidecar 解析） | 提供底层能力；不感知上层流程 |

两条贯穿全局的架构约束，正因为「只有一个编排者」才好实现：

- **懒加载边界**：所有 gmsh/gdstk/gdsfactory 相关适配器都在 `build_geo` **函数体内部**才 import（`geo_build.py:85-90` 及各分支处），
  顶层只 eager-import 纯解析的 `parse_geo_meta_sidecar`。所以 `import quantum_dsl` **不会**拉起任何重依赖——没装 gmsh/gdstk 的环境也能 import。
- **单一 gmsh 会话贯穿两路**（③，`geo_build.py:139-154`）：GDS 路与网格路都通过 `load_geo` Include `qlib.geo`；
  若两路各开各的会话，第二次 Include 会因 include-guard 常量已被 finalize 清掉而报 `Redefinition of function PAD`。
  故由 `build_geo` 持有**一个**会话跨两路，每路只在内部切到各自命名的新 model（模型级仍解耦）。
  同理单位也只在各自入口缩放一次——GDS 路 µm 原样、网格路 µm→m——**绝不双重缩放**。

### 3.4 绑定 key：串起所有阶段

`.geo` 里给每个形状标注一个结构化名字：

```
"<role>::<layer>::<component>::<primitive>"      例: metal::1::Q1::pad_top
```

- 合法 `role`：`metal / ground / jj / substrate`（面）与 `port / symmetry`（标记）—— `schema.py:87-90`。
- 这名字最终被规范化成与旧路径**逐字节一致**的输出组名，模板集中在 `_gmsh_physical.py:44-56`（`PHYSICAL_GROUP_NAMING`）：

  | `.geo` 中的绑定 key | 规范化后组名 | 用途 |
  |---|---|---|
  | `metal::1::Q1::pad_top` | 面 `Q1_pad_top_sfs` | Palace Terminal（导体） |
  | `ground::1::chip::gnd` | 面 `gnd_layer1_sfs` | Palace Ground（接地） |
  | `jj::1::Q1::jj` | `Q1_jj_jj`（GDS layer 20，**不进静电网格**） | lumped 元件 |

- 这条不变量由 `assign_physical_groups`（`_gmsh_physical.py:210-320`）在 OCC `fragment` **之后**逐组重建保证
  （`fragment` 会重排实体编号、抹掉此前的组，所以必须最后统一重建）。

## 4. 能力逐项

### 4.1 几何描述：手写 `.geo`，或只列组件自动生成（带圆角）

**做了什么**
- **手写路径**：直接用原生 Gmsh `.geo`（OCC，µm）写几何，每个面标注绑定 key；loader 解析、校验、登记。
- **自动生成路径**：在 sidecar 里写 `cells:` 块（列组件实例：类型 + 唯一名 + 位置 + 参数），系统自动生成带圆角的 `.geo`，
  **无需手写几何**。圆角来自把路径按半宽做 shapely buffer、预采样成直线段——既出圆角，又保证 GDS 与网格逐字节一致。

**关键实现**
- 几何摄入：`_gmsh_geo_source.py` — `load_geo`（`:178-279`）、`split_geo_name`（`:101-137`，绑定 key → 4 元组校验）、
  `surface_outline_um`（`:379-424`）。
- 组件桥（自动生成）：`geo_emit.py` — `emit_geo`（`:259-413`，把解析好的几何 lower 成扁平 `.geo`，**只 import shapely**）、
  圆角 `_primitive_polygons`（`:213-247`）、合成全芯片 ground 用单个 `BooleanDifference`（`:353-386`）、
  `elaborate_cells`（`:445-547`，每个 cell 跑一次 `build_ir` 复用模板引擎）。

**验证（本次实测）**：`cells_2q.meta.yaml`（无手写几何，两个 `transmon_pocket`）→ 自动生成
`cells_2q.elaborated.geo`，内含 `Physical Surface("metal::1::Q1::…")` 与单个 `BooleanDifference{…}` 的 ground。

> **设计取舍**：合成 ground 必须用 `BooleanDifference` 而非「外环+内孔」的多环面——OCC 把多环面 extrude 成 3D 时会
> **填实孔洞**，「框」就变成实板盖住焊盘（`geo_emit.py:356-358`）。

### 4.2 一份输入，两路产物：GDS 版图 + 仿真网格

**做了什么**：同一份 `.geo` 同时分叉成 **`chip.gds`**（流片用 2D 掩模，gdstk，**微米原样**）和
**`chip.msh`**（3D 四面体体网格，**SI 米**，msh2.2 给 Palace）。两路在各自入口各缩放一次，**绝不双重缩放**。

**关键实现**
- GDS 后端：`gds_adapter.py` — `build_gds`（`:144-269`），`gdstk.Library(unit=1e-6)`（`:190-192`），
  `verify_roundtrip`（`:276-405`，回读自校验）；层映射 `_gds_layers.py`（默认 `metal/ground=(1,0)`、`jj=(20,0)`，`:35-39`）。
- 网格后端：`gmsh_adapter.py` — `build_mesh_from_geo`（`:550-688`）；µm→m 膨胀 `_gmsh_geo_source.py:240-246`；
  尺寸场 `_gmsh_mesh.py:115-178`。
- 统一命名：`_gmsh_physical.py` — `assign_physical_groups`（`:210-320`，fragment 后重建，输出名与旧路径一致）。

**关键修复 / 取舍**
- **JJ 是 lumped 元件**：约瑟夫森结只画进 GDS（layer 20），**不**作为导体网格化——否则会把两焊盘短路、毁掉电容矩阵
  （`_gmsh_geo_source.py:464-477` 移除它）。
- **网格尺寸下限钳位**：`Mesh.MeshSizeMin` 必须 ≤ 任一尺寸场的最小值，改为 `min(min_size, max_size_jj)`
  （`_gmsh_mesh.py:176`），否则几微米的 JJ 区域因网格过粗失败。

**验证（本次实测）**：`chip_layout.meta.yaml` → GDS + 网格（12.3 MB）+ Palace JSON，9 个 physical group。

### 4.3 静电求解：Palace → 电容矩阵

**做了什么**：把网格喂给 Palace（Electrostatic，`L0=1.0`），解出**电容矩阵**并写回结果文件——同时解析两种约定：
**Maxwell 矩阵**（对称、+对角/−非对角，电路量子化用）与**互容矩阵**（全正，对角=对地、非对角=两导体间）。

**关键实现**
- `palace_adapter.py` — `build_palace_config`（`:182-313`）、`run_palace`+`_to_wsl_path`（`:394-439`，WSL 回退）、
  `parse_capacitance_matrix`（`:540-588`，F→fF）、`terminal_bindings`（`:147-175`，矩阵行列**唯一真源**，
  配置与结果共用同一选择函数永不错位）、`write_results_sidecar`（`:630-708`，写 `chip.results.yaml` + provenance）。
- **导体即空腔（关键取舍）**：金属是 PEC 等电位面、不是要填充的体；Palace 要求 Terminal 面是**外边界**。
  于是把金属从真空盒 `occ.cut` 挖空（`carve_conductors`，`_gmsh_layers.py:255-325`），腔壁即外边界；
  `fragment` 后按质心-bbox 归位（`resolve_conductor_faces`，`_gmsh_layers.py:328-385`）。

**验证（本次实测，`two_pads` 2 导体参考，真实求解 151 s）**：Maxwell C 矩阵（fF）

```
[[ 24.7288, -1.9760],
 [ -1.9760, 24.7293]]      ← 对角 +、非对角 −、对称（物理正确）
```

### 4.4 电容矩阵 → 量子比特哈密顿量

**做了什么**：消费电容矩阵，算出量子硬件真正关心的数——每比特频率 `f01`、非谐 `α`、比特对耦合 `g`，写回
`chip.results.yaml`。**纯 Python（仅 `math`）**，任何环境可跑。

**为什么算电容就够（物理依据）**：量子比特工作在 GHz、波长 ~cm，远大于版图特征尺寸 ~100 µm，电磁场可用**集总电路**近似 →
金属焊盘是等电位面，跑一次静电学得电容矩阵，即可经电路量子化得到哈密顿量。

**关键实现**：`circuit_model.py` — `solve_circuit_model`（`:218-323`），**逆电容法**：取量子比特岛子矩阵求逆 `C⁻¹`，
`E_C=(e²/2)[C⁻¹]_ii`、`C_Σ=1/[C⁻¹]_ii`、`E_J=(ħ/2e)²/L_J`、`f01=√(8E_C·E_J)−E_C`、耦合来自 `[C⁻¹]_ij`；
常数取精确 SI-2019，`ħ` 由 `h/2π` 推导（`:60-63`）。

> **设计取舍**：`E_C` **不直接取 Maxwell 对角**——N≥3 时对角会重复计算耦合电容、忽略间接电容路径而漂移；
> 逆电容法严格正确，且对单岛精确退化为 `e²/2C_ii`、对 N=2 退化为教科书 `g` 公式。

**验证（本次实测，`two_pads` + `L_J=10nH`）**：

| 比特 | C_Σ (fF) | E_C (GHz) | E_J (GHz) | f01 (GHz) | α (MHz) | E_J/E_C |
|---|---|---|---|---|---|---|
| A | 24.571 | 0.7883 | 16.346 | **9.3650** | −788.3 | 20.7 |
| B | 24.571 | 0.7883 | 16.346 | **9.3649** | −788.3 | 20.7 |

耦合 A–B：`C_g = 1.976 fF`，`g = 374 MHz`。
