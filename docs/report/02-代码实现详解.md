## 0. 全局心智模型（先记住这 5 句）

1. **两层输入**：几何在 `.geo`（微米），物理参数在 `*.meta.yaml`（材料/网格/层映射/求解器）。
2. **两路输出**：`.geo` 同时分叉成 `chip.gds`（版图，微米原样）和 `chip.msh`（3D 网格，米）→ Palace 解电容。
3. **一个绑定 key**：每个形状在 `.geo` 里有个名字 `role::layer::component::primitive`，所有阶段靠它对齐。
4. **JJ 是 lumped 元件**：约瑟夫森结只画进 GDS（layer 20），**不**作为导体网格化（否则把焊盘短路）。
5. **导体是「挖空」的**：金属焊盘/ground 不是被填充的实体，而是从真空盒里挖掉的空腔——因为静电学里它们是等电位面，
   Palace 要求其表面是外边界。

> 两个最容易被问的「为什么」：
> - **为什么 GDS 用微米、网格用米？** GDS 给流片（gdstk 习惯 µm，`unit=1e-6`），Palace 求解用 SI 米
>   （`L0=1.0`）。两路在各自入口各缩放一次，**绝不双重缩放**。
> - **为什么算电容矩阵就够？** 量子比特工作在 GHz、波长 ~cm ≫ 版图 ~100 µm，电磁场可用集总电路近似 →
>   静电学求电容矩阵 → 电路量子化得哈密顿量。

## 1. 架构与绑定 key（`schema.py` + `_gmsh_physical.py`）

**职责**：定义那个把所有阶段串起来的名字，并保证它最终被规范化成与旧路径**逐字节一致**的输出名。

**核心思路**：与其每个阶段各搞一套 ID，不如让每个形状带**一个字符串**当通用标签：
`"<role>::<layer>::<component>::<primitive>"`，例如 `metal::1::Q1::pad_top`。
- GDS 分支读 `(role, layer)` 决定画到哪个 GDS 层；
- Palace 读最终组名；
- `geo_name_to_group` 是「`.geo` 中命名 → 输出名」的唯一桥（`_gmsh_physical.py:76-105`）。

**名词**：
- **physical group（物理组）**：Gmsh 给一组几何实体起的「名字标签」，下游靠它知道「这个面是金属/这个是地」。
- **fragment（碎裂）**：OpenCASCADE 的布尔操作，把相互重叠的实体切开、**重新分配实体编号**——会抹掉此前定义的物理组。
  所以命名必须在 fragment **之后**统一重建。

| 关键代码 | 位置 | 作用 |
|---|---|---|
| `GEO_SURFACE_ROLES / GEO_MARKER_ROLES / GEO_ROLES` | `schema.py:87-90` | 合法 role：面 `metal/ground/jj/substrate`、标记 `port/symmetry` |
| `GEO_META_ROOT_KEYS` | `schema.py:102` | sidecar 合法顶层键 `{schema,geo,vars,simulation,circuit_model,cells}` |
| 绑定 key 注释块 | `schema.py:79-101` | 文档化 `role::layer::component::primitive` 格式 |
| `PHYSICAL_GROUP_NAMING` | `_gmsh_physical.py:44-56` | **所有输出组名模板**（`{component}_{primitive}`、`gnd_layer{layer}_sfs`…） |
| `geo_name_to_group` | `_gmsh_physical.py:76-105` | 4 元组 → 精确输出名 |
| `_GroupRegistry` | `_gmsh_physical.py:108-138` | 记录已分配组，重名直接报错（绝不静默合并），捕获整数 attribute |
| `assign_physical_groups` | `_gmsh_physical.py:210-320` | **核心**：fragment 后按固定顺序重建每个组，返回 `(groups, attrs)` |

**易被问到的坑**
- **为什么两条前端输出名一致？** 因为不管 YAML 还是 `.geo`，最后都走 `assign_physical_groups` 这一个漏斗
  + 同一套 `PHYSICAL_GROUP_NAMING` 模板。所以 Palace 完全不知道几何来自哪条前端。
- **整数 attribute 是啥？** Palace 不认名字、只认整数标签；`addPhysicalGroup` 的返回值被单独存进 `attrs()`，
  这才是 Palace 引用组的 key。

## 2. `.geo` 摄入与导体挖空（`_gmsh_geo_source.py` + `_gmsh_layers.py`）

**职责**：把手写的 `.geo` 原始几何，变成 GDS 和 Palace 两路都能消费的东西。

**两条单位路径，同一来源**：`load_geo(scale_to_si=False)` 给 GDS 留微米；`scale_to_si=True` 把整模型
µm→m 膨胀（`:240-246`）给网格。**关键次序**：物理组要在膨胀**之前**快照，因为 `occ.dilate` 保留实体编号但抹掉组分配。

**导体即空腔（Approach A）**：静电里金属是 PEC 等电位面，不是要填充的实体；
Palace 要求 Terminal 面是**外边界**（≤1 相邻单元）。所以：
1. `populate_tracker_from_geo` 把金属/ground 面 extrude 成实体，但**暂存**起来（不网格化）；
2. `carve_conductors` 用 `occ.cut` 把它们从真空盒里**挖掉** → 留下导体形状的空腔，腔壁即外边界；
3. `fragment` 后 `resolve_conductor_faces` 按「面质心落在挖前记录的 bbox 里」把腔壁重新归位到各 Terminal。

| 关键代码 | 位置 | 作用 |
|---|---|---|
| `split_geo_name` | `_gmsh_geo_source.py:101-137` | 把绑定 key 拆成 4 元组并校验 |
| `load_geo` | `_gmsh_geo_source.py:178-279` | merge + 同步，膨胀前快照组，校验，返回 `GeoSurface` 列表 |
| `populate_tracker_from_geo` | `_gmsh_geo_source.py:431-511` | metal→`conductor_solids`、ground→`ground_solids`、JJ 移除 |
| JJ 移除 | `_gmsh_geo_source.py:464-477` | `occ.remove`（含物理与网格双重原因注释） |
| `compute_chip_bbox_from_geo` | `_gmsh_geo_source.py:557-588` | 芯片 XY 包围盒（只并金属+ground，排除衬底防循环依赖） |
| `CARVED_GROUND_SUBSTRATE_GAP_SI` | `_gmsh_geo_source.py:64-74` | 有挖空 ground 时把衬底顶面下沉 1 µm（防 z=0 共面让 fragment 失稳） |
| `carve_conductors` | `_gmsh_layers.py:255-325` | 把导体/ground 实体从真空盒 `occ.cut` 挖空 |
| `resolve_conductor_faces` | `_gmsh_layers.py:328-385` | fragment 后按质心-bbox 把腔壁归位（Terminal 先于 ground 判定） |

**关键发现（演示时可主动提）**
- **进程级 Macro 表**：Gmsh 的 `.geo` 解析器把编译过的 Macro 存在进程全局表里，连 `finalize()` 都活着，
  但 include-guard 常量会被重置——所以重新 `Include qlib.geo` 会报「Redefinition of function」。
  解法：每次 load 用一个全新命名的 `gmsh.model`，不 clear/finalize（`:163-220`）。
- **归位顺序不变量**：全芯片 ground 的 XY bbox 忽略它的孔，会在空间上**包住**所有 Terminal；
  所以必须先判 Terminal 再判 ground，否则 ground 会抢走焊盘的腔壁（`_gmsh_layers.py:360-372`）。

## 3. Gmsh 网格管线（`gmsh_adapter.py` + `_gmsh_geometry/_gmsh_layers/_gmsh_mesh.py`）

**职责**：把微米 `.geo` 变成 Palace 要的**水密四面体体网格** `chip.msh`，并给每个重要面打标签。

**流水线**（`build_mesh_from_geo`，`gmsh_adapter.py:550-688`）：load+膨胀 → 填 tracker → 真空盒 →
cut → carve → **fragment** → 命名 → 尺寸场 → 生成 → 写出。

| 关键代码 | 位置 | 作用 |
|---|---|---|
| `build_mesh_from_geo` | `gmsh_adapter.py:550-688` | geo 路径网格入口 |
| `_geo_options_from_sim` | `gmsh_adapter.py:502-547` | sidecar → SI 选项；默认输出 msh2（Palace 读 2.2） |
| `occ.dilate(µm→m)` | `_gmsh_geo_source.py:240-246` | 网格分支唯一的 SI 边界 |
| `apply_cuts` | `_gmsh_layers.py:388-433` | **逐层**把 subtract 从 ground 体里 cut（正向 tone 下基本是 no-op） |
| `fragment_everything` | `_gmsh_layers.py:185-244` | OCC fragment：让共面体共享边界实体（水密所需） |
| `define_size_fields` | `_gmsh_mesh.py:115-178` | Distance→Threshold→Min 尺寸场（导体边/JJ 处加密） |
| **尺寸下限钳位修复** | `_gmsh_mesh.py:176-177` | `effective_min = min(size_min, size_min_jj)`（见下） |
| `write_mesh` | `_gmsh_mesh.py:190-210` | 写 msh2.2，`ScalingFactor=1.0`（已是 SI，不再缩放） |

**易被问到的坑**
- **尺寸下限钳位 bug**（高频，建议熟记）：`Mesh.MeshSizeMin` 必须 ≤ 任一尺寸场的最小值；JJ 加密场的最小值是
  `max_size_jj`（可能比 `min_size` 还小）。若直接用 `min_size`，几微米的 JJ 会被钳到太粗，网格生成报
  「overlapping facets」。修复就是取两者较小值（`_gmsh_mesh.py:176`）。
- **fragment 会消解/拆分实体**：`GeomTracker.remap` 因此区分三种情况（保留 / 替换 / 被消解丢弃，`_gmsh_geometry.py:153-162`）。

## 4. GDS 后端（`gds_adapter.py` + `_gds_layers.py`）

**职责**：把 `.geo` 的 2D 面轮廓**直接**写成 `chip.gds`（流片用的标准 2D 掩模格式），**绕过 3D 网格**。

## 5. Palace 后端 + 结果写回（`palace_adapter.py`）

**职责**：(a) 写 Palace 求解器要的 JSON 输入；(b) 跑 Palace；(c) 把 Palace 输出的电容表读回成人类可读的结果文件。

**名词**：**Terminal**=想算电容的导体；**Maxwell 矩阵**（`terminal-C.csv`，对称、+对角/−非对角，电路量子化用的形式）；
**互容/SPICE 矩阵**（`terminal-Cm.csv`，全正，对角=对地、非对角=两导体间）。两者都解析、F→fF（×1e15）。

**核心不变量**：矩阵行列顺序必须与配置里写 Terminal 的顺序一致。`terminal_bindings`（`:147-175`）是**唯一真源**——
配置生成与结果写回都调同一个 `_conductor_groups`，所以即便选择规则以后改了也不会错位。导体靠 `_sfs` 后缀识别
（排除 `gnd_`/`vacuum`）。

| 关键代码 | 位置 | 作用 |
|---|---|---|
| `build_palace_config` | `palace_adapter.py:182-313` | Electrostatic JSON（Materials/Ground/Terminal/`L0=1.0`，<2 Terminal 报错） |
| `run_palace` + `_to_wsl_path` | `:394-439`, `:376-391` | 优先原生 palace，否则回退 WSL spack Palace 0.16 |
| `parse_capacitance_matrix` | `:540-588` | 读两个 CSV，dry-run 安全（缺文件→available=False） |
| `terminal_bindings` | `:147-175` | 矩阵行列**唯一真源** |
| `write_results_sidecar` | `:630-708` | 写 `chip.results.yaml`（tier 3=仅电容 / 2=+哈密顿量） |

**易被问到的坑**
- **`L0=1.0` 为什么？** 网格在膨胀阶段已变 SI 米，所以一个网格单位=一米，`L0` 保持 1.0；GDS 那路才留微米。**别双重缩放**。
- **tier 是什么？** 完成度标记，数字越小越「派生」：tier 3 = 只有电容矩阵；tier 2 = 电容 + 集总振子哈密顿量。
  代码里只有 3 和 2 两档。
- **provenance 的 SHA-256 在哪算？** 不在本模块，在编排层 `geo_build.py:213-228`（对 geo/mesh/config 取哈希做陈旧检测）。

## 6. emit_geo cell 桥（`geo_emit.py`）——自动生成带圆角几何

**职责**：让旧的高层模板前端（`build_ir`）为新 `.geo` 路径供货——把解析好的 `DesignIR`（已是具体 shapely 几何）
**lower** 成扁平 `.geo` 文本，于是丰富的参数化组件库可被复用，**无需手写几何**。本模块**只 import shapely**。

**核心算法**（`emit_geo`，4 个 pass）：
1. 走每个 primitive，转成填充多边形（`_primitive_polygons`）：实心形原样；线状 path 按半宽 **round buffer**
   → **圆角从这来**；按层分「正向（metal/JJ）」与「subtract（孔）」两桶。
2. 每个正向形 → 一个 OCC `Plane Surface` + `Physical Surface("role::layer::comp::prim")`。
3. **每层合成一张全芯片 ground**：大矩形（覆盖所有特征+margin 或显式 floorplan）unary_union 所有孔 →
   **单个 `BooleanDifference`** 挖孔。
4. 可选把 pin 发成 1D `port::` 标记（默认关）。

`elaborate_cells`（`:445-547`）在上层：对 `cells:` 块每个 cell 调一次 `build_ir`、合并成一个 `DesignIR`
（强制 component 名全局唯一），再调 `emit_geo`。

| 关键代码 | 位置 | 作用 |
|---|---|---|
| `emit_geo` | `geo_emit.py:259-413` | 把 DesignIR lower 成扁平 `.geo` |
| `_primitive_polygons` | `:213-247` | path→round buffer（圆角）；junction→flat cap（干净矩形） |
| `_quad_segs` | `:68-81` | 按弦高容差算每 90° 圆弧的采样段数（圆角精度，clamp[4,64]） |
| `boolean_difference` | `:171-186` | 合成 ground 的单个 OCC 布尔 |
| `elaborate_cells` | `:445-547` | 多 cell → 一份 `<stem>.elaborated.geo` |

**关键发现（演示亮点）**
- **OCC 多环面 extrude 会填实孔**：`geo_emit.py:356-358` 注释明确——多环 `Plane Surface`（外环+内孔环）
  extrude 成 3D 时会把孔填实，「框」就变实板把焊盘盖住。所以 ground 必须用 `BooleanDifference` 而非多环面。
- **圆角在 Python 端预采样成 `Line` 段**：下游 loader 只见直线段，既得到圆角，又保证 GDS 与网格逐字节一致，
  绕开 loader 端弧采样。
- **JJ buffer 用 flat cap + mitre join**（干净矩形），因为它是 lumped 元件；普通 path 用 round（圆角）。

## 7. 电路模型（`circuit_model.py`）—— 电容矩阵 → 量子比特哈密顿量

**职责**：管线的**物理收尾**。读 Palace 的电容矩阵，转成量子硬件设计者真正关心的数：每比特频率 `f01`、
非谐 `α`、比特对耦合 `g`。**纯 Python（仅 `math`）**，任何环境可跑、易单测。

**核心思路（最重要、最可能被追问）**：
- 天真做法是从对角读充电能 `E_C=e²/(2C_ii)`——代码**故意不这么做**。
- 而是：取量子比特岛的子矩阵（fF→F）→ **求逆** `C⁻¹` → `E_C=(e²/2)[C⁻¹]_ii`、`C_Σ=1/[C⁻¹]_ii`、
  耦合来自 `[C⁻¹]_ij`。
- **为什么求逆**：N≥3 时天真对角会重复计算共享耦合电容、忽略间接电容路径而漂移；逆电容法严格正确，
  且对单岛**精确退化**为 `e²/2C_ii`、对 N=2 退化为教科书 `g` 公式（所以简单情形不丢精度）。
- 再算 `E_J=(ħ/2e)²/L_J`、`f01=(√(8E_C·E_J)−E_C)/h`、`α=−E_C`。常数取精确 SI-2019，`ħ` 由 `h/2π` **推导**。

| 关键代码 | 位置 | 作用 |
|---|---|---|
| 物理常数（`ħ` 推导） | `circuit_model.py:60-63` | 精确 SI-2019，`HBAR=H/2π` 非硬编码字面量 |
| `_invert_matrix` | `:185-211` | 纯 Python 高斯-约当求逆（无 numpy），近奇异报错 |
| `solve_circuit_model` | `:218-323` | 入口：守卫 + 子矩阵求逆 + 每比特哈密顿量 + 比特对 `g` |
| 每比特 `E_C` + 非 transmon 守卫 | `:275-306` | `E_C=0.5e²[C⁻¹]_ii`；`f01≤0` 报清晰 `DesignDslError` |

**易被问到的坑**
- **未被任何比特引用的 Terminal**=固定电位的接地电极，其电容已折进对角，所以**正确地**不进子矩阵。
- **`f01≤0` 守卫**：`E_J/E_C<1/8`（非 transmon 区）会得非物理 `f01`，代码报清晰错误而非泄漏裸 `ValueError`。
- **多岛（floating/differential）**：schema 预留但当前不解，会明确报「暂不支持」。

  因为它自己的 `Component.plot()` API 跨版本不稳定（`:248-254`）。
- **所有重依赖懒加载**：`import quantum_dsl` 不会拉进 gdstk/matplotlib/gdsfactory（有纯净性测试守着）。

## 9. CLI 编排 + sidecar 解析（`geo_build.py` + `parsers/simulation.py`）

**职责**：胶水层。读 sidecar、选几何源、从一个入口 `build_geo()` 驱动两路后端。

**编排顺序**（`build_geo`，`geo_build.py:55-267`，**是本模块的核心**）：
解析 sidecar → 选几何源（有 `cells:` 就 `elaborate_cells` 生成 `<stem>.elaborated.geo`，否则用 `geo:`/`--geo`）→
分叉 GDS（µm）+ 网格（m）→ 建/校验/写 Palace 配置 → 可选跑 Palace → 实解才解析 C 矩阵 → 可选电路模型 →
写 `chip.results.yaml` → 可选 PNG。

| 关键代码 | 位置 | 作用 |
|---|---|---|
| `build_geo` | `geo_build.py:55-267` | 顶层编排 |
| 单一 gmsh 会话守卫 | `geo_build.py:139-171` | 两路共享一个会话（见下坑） |
| `main`（CLI） | `geo_build.py:274-331` | `--geo/--out-dir/--run-palace/--dry-run/--png` |
| `parse_geo_meta_sidecar` | `parsers/simulation.py:860-941` | 校验顶层键、解析 cells、要求恰好一个几何源 |
| `_parse_unit_value` | `parsers/simulation.py:131-167` | SI 前缀**缩放**解析（`10nH`→1e-8 H），禁裸数 |

**易被问到的坑**
- **为什么两路共享一个 gmsh 会话？**（高频）`qlib.geo` 的 `PAD/CPW` 宏存在**进程全局**解析表里，连
  finalize 都活着，但它的 include-guard 常量不会活——若每路各自 finalize 自己的会话，第二次 `Include`
  会在 guard 丢失下重跑、崩在「Redefinition of function PAD」。所以 `build_geo` 开**一个**会话跨两路，
  `_did_initialize` 守卫保证不提前 finalize。
- **单位解析有两个相似但相反的函数**：`_parse_scalar_with_optional_unit` 校验后**丢弃**单位（适合 `50ohm`）；
  `_parse_unit_value` 按 SI 前缀**相乘**（`10nH`→1e-8 H）且**禁裸数**（`10 H` 与 `10 nH` 差 1e9，不能含糊）。

## 10. 预期问答（演示前务必过一遍）

**Q：这个 DSL 解决什么问题？**
A：把超导量子芯片的描述拆成「几何（`.geo`，µm）+ 物理（`*.meta.yaml`）」两层，一键产出流片版图（GDS）和
静电仿真（Palace 电容矩阵），再把电容矩阵转成量子比特哈密顿量。用户甚至可以不写几何，用 `cells:` 块列模板实例即可。

**Q：那个 `metal::1::Q1::pad_top` 是什么？**
A：绑定 key——`role::layer::component::primitive`。它是贯穿几何/GDS/Palace/电路模型的唯一标签；
最终被规范化成与旧路径逐字节一致的组名（`metal::1::Q1::pad_top` → 面 `Q1_pad_top_sfs`）。

**Q：为什么导体要从真空里「挖空」，而不是当实体网格化？**
A：静电学里金属是等电位面（PEC），不是要填充的体。Palace 要求 Terminal 面是外边界（≤1 相邻单元）；
把金属挖成空腔，腔壁天然是外边界。若当实板网格化，其表面是内面（2 相邻单元），MFEM 求解时会拒绝。

**Q：约瑟夫森结（JJ）为什么不网格化？**
A：JJ 是 lumped（集总）电路元件——一个非线性电感，由 `L_J`/`E_J` 表征。把它当导体网格化会把它连接的两个焊盘
**短路**，电容矩阵就没意义了；而且薄面嵌在金属里会触发网格「overlapping facets」。所以它只画进 GDS layer 20，
求解时从网格里移除。

**Q：电容矩阵怎么变成量子比特频率的？为什么不直接用 Maxwell 对角？**
A：取量子比特岛子矩阵 → **求逆** → `E_C=(e²/2)[C⁻¹]_ii`，再 `f01=√(8E_C·E_J)−E_C`。不直接用对角是因为
N≥3 时对角会重复计算耦合电容、忽略间接电容路径而漂移；逆电容法严格正确，且对单岛精确退化为 `e²/2C_ii`。

**Q：为什么 GDS 是微米、网格是米？会不会缩放两次？**
A：GDS 给流片，gdstk 习惯 µm（`unit=1e-6`，原样穿过）；Palace 求解用 SI 米（`L0=1.0`）。两路在各自入口各缩放一次，
代码里有显式注释和 `verify_roundtrip` 守着，**不会**双重缩放。

**Q：圆角是怎么来的？**
A：`emit_geo` 把线状 path 按半宽做 shapely **round buffer**，圆角在 Python 端预采样成直线段
（精度由弦高容差控制）。下游只见直线段，所以 GDS 与网格逐字节一致。

**Q：测试覆盖如何？**
A：本次实测 **314 passed, 3 skipped**（187.7 s，metal-env）。3 个 skip 是 1 个门控 live Palace 测试
（`QDSL_RUN_PALACE=1` 时通过）+ 2 个「gdsfactory 缺失回退」互斥测试（因 gdsfactory 已装而跳过）。

**Q：GDSFactory 用在哪？**
A：只用于**可视化**——`gds_viz` 只读成品 `chip.gds`，`to_gdsfactory_component=gf.import_gds` 把版图接入
gdsfactory 生态。它**不是** emitter（版图仍由 gdstk 写）。

**Q：哪些没做 / 后续？**
A：本阶段（圆角 cell + 静电电容矩阵）已全部完成。显式延后（未否决，均为纯增量）：端口绑定 / sidecar schema
校验文档；本征模/驱动/损耗求解器；层级/多金属层/flip-chip。名字→属性的绑定是 solver-agnostic 的，更强求解器回来时是纯增量。

**Q：Palace 是什么？跑在哪？**
A：开源有限元电磁求解器（这里用 Electrostatic 模式解电容）。环境里经 spack 装的 Palace 0.16，
`run_palace` 在 Windows 上会自动回退到 WSL；本机 WSL 直接跑（`PALACE_BIN` 已持久化在 env 里）。
