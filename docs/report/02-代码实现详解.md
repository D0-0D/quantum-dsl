## 0. 全局心智模型（先记住这 5 句）

1. **两层输入**：几何在 `.geo`（微米），物理参数在 `*.meta.yaml`（材料/网格/层映射/求解器）。
2. **两路输出**：`.geo` 同时分叉成 `chip.gds`（版图，微米原样）和 `chip.msh`（3D 网格，米）→ Palace 解电容。
3. **一个绑定 key**：每个形状在 `.geo` 里有个名字 `role::layer::component::primitive`，所有阶段靠它对齐。
4. **JJ 是 lumped 元件**：约瑟夫森结只画进 GDS（layer 20），**不**作为导体网格化（否则把焊盘短路）。
5. **导体是「挖空」的**：金属焊盘/ground 不是被填充的实体，而是从真空盒里挖掉的空腔——因为静电学里它们是等电位面，
   Palace 要求其表面是外边界。

> 两个最容易被问的「为什么」：
> - **为什么 GDS 用微米、网格用米？** GDS 给流片（gdstk 习惯 µm，`unit=1e-6`），Palace 求解用 SI 米
>   （`L0=1.0`）。两路在各自入口各缩放一次，**绝不双重缩放**。
> - **为什么算电容矩阵就够？** 量子比特工作在 GHz、波长 ~cm ≫ 版图 ~100 µm，电磁场可用集总电路近似 →
>   静电学求电容矩阵 → 电路量子化得哈密顿量。

### 0.1 全局调用链：一条命令 `build_geo` 串起全程

## 1. 绑定 key 与命名：所有阶段对齐的“一根线”（`schema.py` + `_gmsh_physical.py`）

**做什么**：让每个形状带**一个字符串**当通用标签 `"<role>::<layer>::<component>::<primitive>"`（例
`metal::1::Q1::pad_top`），并保证它最终被规范化成与旧路径**逐字节一致**的输出名，下游 Palace 因此对几何来源无感。

**第一段真实代码——命名模板表**（`_gmsh_physical.py:44-56`）。这是“所有输出名长什么样”的**唯一**定义：

```python
PHYSICAL_GROUP_NAMING = {
    "ground_volume":    "gnd_layer{layer}",          # 金属地的体
    "ground_surface":   "gnd_layer{layer}_sfs",      # 金属地的外表面（Palace Ground）
    "substrate_volume": "substrate_layer{layer}",    # 介质衬底的体
    "component_volume":   "{component}_{primitive}",      # 焊盘的体
    "component_surface":  "{component}_{primitive}_sfs",  # 焊盘的外表面（Palace Terminal）
    "junction_surface":   "{component}_{primitive}_jj",   # JJ（2D 面，不进静电网格）
    "vacuum_volume":  "vacuum",
    "vacuum_outer":   "vacuum_outer",                # 真空外边界（也接地）
    …
}
```

**第二段——把绑定 key 翻成上面的名字**（`geo_name_to_group`，`:76-105`）。就是一个 `role` 分支：

```python
def geo_name_to_group(role, layer, component="", primitive=""):
    if role == "metal":
        name = PHYSICAL_GROUP_NAMING["component_volume"].format(component=component, primitive=primitive)
    elif role == "ground":
        name = PHYSICAL_GROUP_NAMING["ground_volume"].format(layer=layer)
    elif role == "substrate":
        name = PHYSICAL_GROUP_NAMING["substrate_volume"].format(layer=layer)
    elif role == "jj":
        name = PHYSICAL_GROUP_NAMING["junction_surface"].format(component=component, primitive=primitive)
    …
    return _sanitize(name)     # 把 . - 空格 等非法字符换成 _，数字开头加 g_
```

**所以绑定 key 的去向是确定的**（演示时可直接念这张表）：

| `.geo` 里写的名字 | 体组名（dim=3） | 面组名（dim=2） | Palace 角色 |
|---|---|---|---|
| `metal::1::Q1::pad_top` | `Q1_pad_top` | `Q1_pad_top_sfs` | **Terminal**（导体） |
| `ground::1::chip::gnd` | `gnd_layer1`（挖空路径下只剩面） | `gnd_layer1_sfs` | **Ground** |
| `substrate::3::…` | `substrate_layer3` | — | 介质材料 |
| `jj::1::Q1::jj` | — | `Q1_jj_jj`（→ GDS layer 20，**不进网格**） | lumped |

**第三段——真正登记到 gmsh 的地方**（`_GroupRegistry.add`，`:121-131`）。一行关键 API：

```python
def add(self, name, dim, tags):
    sane = _sanitize(name)
    if sane in self._taken:
        raise ValueError(f"physical group name {sane!r} reused …")   # 重名直接报错，绝不静默合并
    attr = gmsh.model.addPhysicalGroup(dim=dim, tags=tags, tag=-1, name=sane)  # ← 给一组实体起名，返回整数 attr
    self._taken[sane] = (dim, list(tags))
    self._attrs[sane] = int(attr)        # ← 这个整数才是 Palace 引用组的 key（Palace 不认名字、只认整数）
```

**易被问到的坑**
- **为什么两条前端输出名一致？** 不管手写 `.geo` 还是 `cells:` 自动生成，最后都走 `assign_physical_groups`
  （`:210-320`）这**一个漏斗** + 同一套模板表。所以 Palace 完全不知道几何来自哪条前端。
- **整数 attribute 是啥？** `addPhysicalGroup` 的返回值。名字给人看，整数给 Palace 用——`palace_adapter` 全程用整数引用组。
- **为什么命名要在 fragment 之后做？** 见 §3：`fragment` 会重排实体编号并抹掉旧组，所以命名必须最后统一重建。

## 2. `.geo` 摄入：手写的几何是什么、怎么读进来（`_gmsh_geo_source.py` + `_gmsh_layers.py`）

> 这一节正面回答两个高频问题：**①「原生 geo 用什么指令 build 的？」②「读进来用的什么 API？」**

### 2A. 手写 `.geo` 里到底写了什么指令

`.geo` 不是普通数据文件，而是一段 **Gmsh 脚本**（OpenCASCADE 内核）；`gmsh.merge` 会**执行**它。看真实的
`examples/dsl/geo/chip_layout.geo`（裁剪）：

```gmsh
SetFactory("OpenCASCADE");        // 用 OCC 几何内核（布尔/extrude 都靠它）
Include "qlib.geo";               // 引入宏库：PAD / CPW / JUNCTION / GROUND_CUTOUT

cpw_w = 10; pad_w = 120; pad_h = 80;   // 普通变量（µm）

// —— 画一条 CPW 中心导体：给宏设入参变量 → Call 宏 → 把它的返回面贴绑定 key ——
x1=-400; y1=0; x2=400; y2=0; width=cpw_w;
Call CPW;                                       // ← 调用 qlib.geo 里的宏
Physical Surface("metal::1::BUS::trace") = { sret };   // ← 绑定 key 就贴在这

// —— 一块焊盘 ——
cx=-200; cy=235; w=pad_w; h=pad_h;
Call PAD;
Physical Surface("metal::1::Q1::pad_top") = { sret };
```

**`Call XXX` 是调用 `qlib.geo` 里的宏（Macro）**。宏用**约定变量传参/返回**：调用前给 `x1/y1/x2/y2/width`
（或 `cx/cy/w/h`）赋值，宏把生成的面 tag 塞进全局变量 `sret`，下一行 `Physical Surface("…") = { sret }` 给它贴名。
看宏库 `qlib.geo` 里 `PAD` / `CPW` 的真身（`examples/dsl/geo/qlib.geo:36-64`）：

```gmsh
Macro PAD                                       // PAD(cx,cy,w,h) —— 一个矩形焊盘
  sret = news;                                  // news = 申请一个新 surface tag
  Rectangle(sret) = { cx - w/2, cy - h/2, 0, w, h };
Return

Macro CPW                                       // CPW(x1,y1,x2,y2,width) —— 两点间的中心导体矩形
  _dx = x2-x1; _dy = y2-y1; _len = Sqrt(_dx*_dx + _dy*_dy);
  _nx = -_dy/_len; _ny = _dx/_len;  _hw = width/2;   // 单位法向 × 半宽
  _p1 = newp; Point(_p1) = { x1+_nx*_hw, y1+_ny*_hw, 0 };   // 四个角点
  …                                                          // _p2 _p3 _p4
  _cl = newll; Curve Loop(_cl) = { _l1,_l2,_l3,_l4 };
  sret = news; Plane Surface(sret) = { _cl };   // 四条边围成面，tag 写回 sret
Return
```

要点：
- **宏 = 把“中心线+宽度”这种参数翻译成裸 OCC 的 `Point/Line/Curve Loop/Plane Surface`**。`newp/newl/newll/news`
  是 gmsh 的“申请下一个空闲 point/line/loop/surface 编号”。
- **宏只产几何、不贴名**（这是 `qlib.geo` 开头写死的约定）：贴 `Physical Surface(...)` 由**调用者**做，于是同一个几何宏
  能被任意 role 复用。
- **`GROUND_CUTOUT` 用布尔减法挖 CPW gap**（`qlib.geo:94-101`）：先用 `CPW` 宏画出 gap 工具面，再
  `BooleanDifference{ Surface{ground}; Delete; }{ Surface{tool}; Delete; }` 从 ground 面上挖掉它。
- **重复 Include 的防护**：`qlib.geo` 用 `If(!Exists(_QLIB_INCLUDED)) … EndIf` 包住所有宏（`:30-103`），
  否则第二次 Include 会报 `Redefinition of function`（这条防护正是 §9“两路共享一个会话”那个坑的根源）。
- **衬底可以不画**：本例没有 `substrate::` 面，由网格分支按 chip bbox 自动补一块介质（见 §3 的 `ensure_dielectric_substrates`）。

> 对比：**自动生成路径（§6 的 `emit_geo`）不用这些宏**，它直接吐裸 OCC 的 `Plane Surface` / `BooleanDifference`。
> 两条来源最终都落到同样的 `Physical Surface("role::…")` 名——这就是“几何来源无感”的根。

### 2B. `load_geo` 用哪些 gmsh API 把 `.geo` 读成模型（`_gmsh_geo_source.py:178-279`）

真实主干（裁剪）：

```python
def load_geo(path, *, scale_to_si=False):
    …
    gmsh.model.add(model_name); gmsh.model.setCurrent(model_name)  # 每次 load 用一个全新命名的 model
    gmsh.merge(str(path))                  # ① 执行 .geo 脚本：把所有 Point/Line/Surface/Call… 在 OCC 里建出来
    gmsh.model.occ.synchronize()           # ② 把 OCC 内核里建的实体推进“可查询的 gmsh 模型”

    raw = []                               # ③ 先快照物理组（必须在 dilate 之前！）
    for dim in (1, 2):
        for (d, tag) in gmsh.model.getPhysicalGroups(dim):
            name = gmsh.model.getPhysicalName(d, tag)
            ents = gmsh.model.getEntitiesForPhysicalGroup(d, tag)
            raw.append((d, name, ents))

    if scale_to_si:                        # ④ 仅网格分支：整模型缩放 µm→m
        gmsh.model.occ.dilate(gmsh.model.getEntities(), 0,0,0,
                              SI_PER_INTERNAL, SI_PER_INTERNAL, SI_PER_INTERNAL)  # 1e-6
        gmsh.model.occ.synchronize()

    bad = lint_geo_names([n for (_d, n, _e) in raw])   # ⑤ 校验所有名字符合 :: 约定
    if bad: raise DesignDslError(…)
    # … 按 role 校验维度（面 role 必须 dim=2，marker 必须 dim=1），返回 GeoSurface 列表
```

逐段：
- **① `gmsh.merge(path)`**：这一行就是“build 原生 geo”的动作——它**运行** `.geo` 脚本，`Call PAD` 等都在此刻被执行成真实 OCC 实体。
- **② `occ.synchronize()`**：OCC 内核里刚建的实体此刻还不在 gmsh 的“模型”里，sync 之后才能 `getPhysicalGroups`/`getBoundary`。
- **③ 先快照物理组**：把每个 `::` 名和它的实体 tag 记下来。**为什么要先**？下一步 `occ.dilate` 保留实体 tag、但会
  **抹掉**组分配——所以必须在 dilate 前抓快照（这是本模块最易踩的坑）。
- **④ `occ.dilate(…, 1e-6,1e-6,1e-6)`**：把整模型按 1e-6 缩放，微米→米。GDS 分支 `scale_to_si=False` 跳过、保持 µm。
- **返回 `GeoSurface` 列表**：每条 = `(role, layer, component, primitive, dim, entities)`，下游网格/GDS 都消费它。

> 口诀：**merge → sync → 快照组 →（可选）dilate → 校验**。

### 2C. GDS 那路怎么从面取出轮廓（`surface_outline_um`，`:379-424`）

GDS 不 extrude、只要 2D 轮廓。做法：`getBoundary(combined=False, oriented=True)` 拿到一个面的所有边界曲线 →
逐条采样成点（`Line` 取两端点；圆弧按 `arc_tol` 采样）→ head→tail 拼成闭环 → 用 **shoelace 有符号面积**给环排序
（最大的是外轮廓，其余是孔）。返回 `(exterior, [holes…])` 给 §4 的 gdstk。

### 2D. JJ 移除 + 导体挖空（`_gmsh_layers.py`，关键取舍）

- **JJ 不 extrude**：`populate_tracker_from_geo`（`_gmsh_geo_source.py:431-511`）把 metal/ground 面 extrude 成 3D 体，
  但 `jj::` 面只平移到层中心、记进 `tracker.juncs`，**不**当导体——否则会把它桥接的两块焊盘短路，电容矩阵作废。
- **导体即空腔（Approach A）**：静电里金属是 PEC 等电位面、不是要填充的体；Palace 要求 Terminal 面是**外边界**。
  `carve_conductors`（`_gmsh_layers.py:255-325`）把金属体从真空盒 `occ.cut` **挖掉**，留下导体形状的空腔，腔壁即外边界：

```python
new_vac, _ = gmsh.model.occ.cut([(3, tracker.vacuum_box)], cut_tools,
                                removeObject=True, removeTool=True)   # 从真空盒里减掉所有导体体
```

  挖之前先记下每个导体的 3D bbox（`conductor_bbox`），`fragment` 之后 `resolve_conductor_faces`（`:328-385`）按
  “腔壁质心落在哪个 bbox 里”把每片腔壁归位到对应 Terminal。**判定顺序**：先判小而具体的 Terminal、再判全芯片 ground，
  否则 ground 的大 bbox 会抢走焊盘的腔壁（`:360-372`）。

## 3. 网格管线：从 `.geo` 到水密四面体（`gmsh_adapter.py` + `_gmsh_layers/_gmsh_mesh.py`）

**做什么**：把微米 `.geo` 变成 Palace 要的**水密四面体体网格** `chip.msh`，并给每个重要面打标签。

**主干——`build_mesh_from_geo`（`gmsh_adapter.py:550-688`）的阶段流水线**（裁剪、保留真实调用）：

### 3A. fragment 到底做了什么、怎么发生的（`fragment_everything`，`_gmsh_layers.py:185-244`）

**要解决的问题**：两个实体（如真空盒和挖出的衬底、或相邻两块金属）在某个面相接时，OCC 里它们**各自持有一份独立的接触面**。
网格器分别剖分两份面 → 界面两侧节点对不齐 → 网格不“水密/共形” → Palace 解不了。`fragment` 就是把所有相接实体在交界处
**切开、并强制共享同一个边界面**，使界面共形。

**真实代码**：

```python
inputs_3d = [...]        # 收集所有 3D 体：ground / 焊盘 / path / vacuum_box
inputs_2d = [...]        # 收集 2D 的 JJ 面（+ 预留的 port 面）
all_inputs = inputs_3d + inputs_2d
object_dimtag = all_inputs[0]      # 任取第一个当 object
tools         = all_inputs[1:]     # 其余当 tools
out_dimtags, out_map = gmsh.model.occ.fragment([object_dimtag], tools)   # ← 这一行做切割

ordered_inputs = [object_dimtag] + tools
old_to_new = {}
for old, mapping in zip(ordered_inputs, out_map):   # out_map[i] 与 inputs[i] 一一对齐
    old_to_new[old] = list(mapping)                 # = “第 i 个输入 fragment 后变成了哪些实体”
tracker.remap(old_to_new)                           # 用映射更新 tracker 里所有 tag 表
gmsh.model.occ.synchronize()
```

逐段：
- **`occ.fragment([object], tools)`** 返回两样东西：`out_dimtags` 是切完后所有实体的平铺列表；`out_map` 是**按输入对齐**
  的列表——`out_map[i]` 告诉你“第 i 个输入实体变成了哪些新实体”（是个列表，因为一个体可能被切成多块）。
- **`old_to_new` + `tracker.remap`**：fragment 会**重排/拆分实体编号**，于是 tracker 里记的旧 tag 全部失效。把
  `out_map` 拼成“旧 tag → 新 tag 列表”交给 `remap` 批量更新。`remap` 区分三种命运：保留 / 被替换 / 被消解丢弃
  （`_gmsh_geometry.py:153-162`）。
- **副作用 + 次序**：fragment 还会**抹掉此前的物理组**。所以它在管线里**居中**——必须在 `carve_conductors`（挖空）
  **之后**、在 `assign_physical_groups`（命名）和 `resolve_conductor_faces`（归位）**之前**。命名/归位都靠 fragment 后
  “干净的最终几何”重新判定。

**核心循环**（`build_gds`，`:144-269`，裁剪）：


```python
def plane_surface(self, polygon):
    # 对每个角点发 Point，相邻点连 Line，围成 Curve Loop，最后 Plane Surface
    self.raw(f"{p} = newp; Point({p}) = {{ {x}, {y}, 0 }};")
    self.raw(f"{ln} = newl; Line({ln}) = {{ {a}, {b} }};")
    self.raw(f"{cl} = newll; Curve Loop({cl}) = {{ … }};")
    self.raw(f"{s} = news; Plane Surface({s}) = {{ {cl} }};")

def boolean_difference(self, base, tools):
    self.raw(f"{d}() = BooleanDifference{{ Surface{{ {base} }}; Delete; }}{{ … Delete; }};")
```

所以 `cells_2q.elaborated.geo` 顶部是 `// AUTO-GENERATED …`、中间一堆 `Point/Line/Plane Surface` + `Physical Surface("metal::1::Q1::pad_top")`、

## 7. 电路模型：电容矩阵 → 量子比特哈密顿量（`circuit_model.py`）

**做什么**：读 Palace 的电容矩阵，算每比特频率 `f01`、非谐 `α`、比特对耦合 `g`。**纯 Python（仅 `math`）**，任何环境可跑。

**核心思路（最可能被追问）**：不是天真地从对角读 `E_C=e²/2C_ii`，而是**取量子比特岛子矩阵求逆**。真实代码
（`solve_circuit_model`，`:218-323`，裁剪）：

```python
# 1) 用 terminal 绑定把“岛组名”映射成矩阵行列号（与 §5 同一真源）
group_to_idx = { b.group: (b.index - 1) for b in cap_result.terminals }
node_idx = [ group_to_idx[q.islands[0]] for q in qubits ]      # 每个 qubit 引用一个岛

# 2) 取这些节点的子矩阵（fF→F），求逆
sub  = [[ maxwell[a][b] * 1e-15 for b in node_idx] for a in node_idx]
cinv = _invert_matrix(sub)                                     # = C⁻¹（法拉⁻¹）

# 3) 每比特：E_C / C_Σ / E_J / f01 / α
for k, q in enumerate(qubits):
    e_c = 0.5 * ELEM_CHARGE**2 * cinv[k][k]      # E_C = (e²/2)·[C⁻¹]_kk   （焦耳）
    e_j = q.e_j_joule()                          # E_J = (ħ/2e)²/L_J
    f01 = (sqrt(8*e_c*e_j) - e_c) / H_PLANCK     # f01 = (√(8 E_C E_J) − E_C)/h
    c_sigma = 1.0 / cinv[k][k]                   # C_Σ = 1/[C⁻¹]_kk
    # α = −E_C；EJ_over_EC = e_j/e_c …

# 4) 每对比特的耦合 g（来自 C⁻¹ 的非对角）
for i, j in pairs:
    prefactor = abs(cinv[i][j]) / sqrt(cinv[i][i]*cinv[j][j])
    g_hz = 0.5 * prefactor * sqrt(f_i * f_j)
```

**为什么求逆**（演示亮点）：N≥3 时天真对角会**重复计算共享耦合电容、忽略间接电容路径**而漂移；逆电容法严格正确，
且对单岛**精确退化**为 `e²/2C_ii`、对 N=2 退化为教科书 `g` 公式。求逆本身是纯 Python 高斯-约当（`_invert_matrix`，`:185-211`，
无 numpy；近奇异报错）。常数取精确 SI-2019，`ħ = h/2π` **推导**而非硬编码字面量（`:60-63`）。

**具体数据怎么连起来**（`two_pads` + `L_J=10nH`）：Maxwell 对角 ≈ 24.73 fF、非对角 −1.98 fF → 求逆 → 每比特
`C_Σ≈24.57 fF` → `E_C≈0.788 GHz`；`L_J=10nH → E_J≈16.3 GHz`；`f01=√(8·0.788·16.3)−0.788 ≈ 9.365 GHz`；`α=−E_C≈−788 MHz`；
两比特 `g≈374 MHz`。

**坑**：未被任何比特引用的 Terminal = 固定电位接地电极，其电容已折进对角，所以**正确地**不进子矩阵；`f01≤0`
（`E_J/E_C<1/8`，非 transmon 区）会报清晰 `DesignDslError` 而非泄漏裸 `ValueError`。

```python
        if meta.get("circuit_model"):
            circuit_model = solve_circuit_model(cap, junctions)                      # → 哈密顿量
        write_results_sidecar(cap, out_dir/"chip.results.yaml", circuit_model=circuit_model)
```

**易被问到的坑（高频）——为什么两路共享一个 gmsh 会话？**（`:139-154`）`qlib.geo` 的 `PAD/CPW` 宏存在**进程全局**
解析表里，连 `finalize` 都活着，但它的 include-guard 常量 `_QLIB_INCLUDED`（见 §2A）**不会**活——若每路各自
`finalize` 自己的会话，第二次 `Include "qlib.geo"` 会在 guard 丢失下重跑宏定义、崩在 `Redefinition of function PAD`。
所以 `build_geo` 开**一个**会话跨两路，`_did_initialize` 守卫保证“只 finalize 我们自己开的”。

**sidecar 解析**（`parse_geo_meta_sidecar`，`parsers/simulation.py:860-941`）：校验顶层键 ⊆ `{schema,vars,simulation,circuit_model,cells}`、
解析 `cells`、要求恰好一个几何源。单位解析 `_parse_unit_value`（`:131-167`）按 SI 前缀**相乘**（`10nH`→1e-8 H）且**禁裸数**。

## 10. 预期问答（演示前务必过一遍）

**Q：原生 `.geo` 是用什么指令 build 出来的？**
A：`.geo` 是一段 Gmsh OCC 脚本。手写路径靠 `Include "qlib.geo"` 引入宏，用 `Call PAD/CPW/JUNCTION` 把“中心线+宽度”
翻成 `Point/Line/Curve Loop/Plane Surface`，宏把结果面写进全局变量 `sret`，作者再 `Physical Surface("metal::…")={sret}`
贴绑定 key。Python 端 `load_geo` 用 `gmsh.merge()` **执行**这个脚本、`occ.synchronize()` 推进模型、`getPhysicalGroups`
枚举名字（详见 §2）。

**Q：什么是 fragment？为什么必须在它之后才命名？**
A：`gmsh.model.occ.fragment([object], tools)` 把所有相接的实体在交界处切开并**共享同一个边界面**，否则界面两侧网格节点
对不齐、不水密、Palace 解不了。它返回 `out_map`（按输入对齐的“旧→新”映射），用来 `tracker.remap` 更新所有 tag。
fragment 会重排编号并**抹掉旧物理组**，所以命名（`assign_physical_groups`）必须在它**之后**统一重建（详见 §3A）。

**Q：`cells:` 用的模板放在哪、怎么实现的？**
A：模板是 `src/quantum_dsl/dsl_templates/` 下的 **YAML 文件**（如 `qubits/transmon_pocket.yaml`），靠 `extends` 继承
（transmon_pocket→base_qubit→qcomponent），几何里用 `${options.pad_width}` 之类表达式参数化。`elaborate_cells` 对每个
cell 拼一个最小 design 调 `build_ir`（复用 v3 引擎）得到含 shapely 几何的 `DesignIR`，再用 `emit_geo` lower 成扁平 `.geo`（详见 §6）。

**Q：圆角是怎么来的？**
A：`emit_geo._primitive_polygons` 把线状 path 用 shapely `geom.buffer(half, join_style="round")` 膨胀成带圆角的多边形，
`_quad_segs` 按弦高容差把圆弧**预采样成直线段**。下游只见直线段，所以 GDS 与网格逐字节一致（§6D）。

**Q：那个 `metal::1::Q1::pad_top` 是什么？怎么保证两条前端输出名一致？**
A：绑定 key——`role::layer::component::primitive`。不管手写还是自动生成，最后都走同一个 `assign_physical_groups`
漏斗 + 同一套 `PHYSICAL_GROUP_NAMING` 模板（§1），规范化成 `Q1_pad_top_sfs` 这种名，所以 Palace 对几何来源无感。

**Q：为什么导体要从真空里「挖空」，而不是当实体网格化？**
A：静电里金属是等电位面（PEC），不是要填充的体。Palace 要求 Terminal 面是外边界（≤1 相邻单元）；把金属 `occ.cut`
挖成空腔，腔壁天然是外边界。若当实板网格化，其表面是内面（2 相邻单元），MFEM 会拒绝（§2D）。

**Q：约瑟夫森结（JJ）为什么不网格化？**
A：JJ 是 lumped 元件（一个非线性电感，由 `L_J`/`E_J` 表征）。当导体网格化会把它桥接的两焊盘**短路**，电容矩阵作废；
薄面嵌在金属里还会触发 `overlapping facets`。所以它只画进 GDS layer 20，求解时移除（§2D）。

**Q：电容矩阵怎么变成量子比特频率的？为什么不直接用 Maxwell 对角？**
A：取量子比特岛子矩阵→**求逆**→`E_C=(e²/2)[C⁻¹]_ii`，再 `f01=√(8E_C·E_J)−E_C`。不直接用对角是因为 N≥3 时对角会
重复计算耦合电容、忽略间接路径而漂移；逆电容法严格正确，对单岛精确退化为 `e²/2C_ii`（§7）。

**Q：为什么 GDS 是微米、网格是米？会不会缩放两次？**
A：GDS 给流片（`unit=1e-6`，原样穿过）；Palace 求解用 SI 米（`L0=1.0`）。两路在各自入口各缩放一次——GDS 分支
`load_geo(scale_to_si=False)` 不缩放，网格分支 `scale_to_si=True` 做 `occ.dilate(1e-6)`，写网格时 `ScalingFactor=1.0`
不再缩放。`verify_roundtrip` 还回读 GDS 守着，**不会**双重缩放。

**Q：测试覆盖如何？**
A：本次实测 **314 passed, 3 skipped**（187.7 s，metal-env）。3 个 skip = 1 个门控 live Palace 测试
（`QDSL_RUN_PALACE=1` 时通过）+ 2 个「gdsfactory 缺失回退」互斥测试（因 gdsfactory 已装而跳过）。

**Q：Palace 是什么？跑在哪？**
A：开源有限元电磁求解器（这里用 Electrostatic 模式解电容）。环境里经 spack 装的 Palace 0.16，`run_palace` 在
Windows 上会自动回退到 WSL；本机 WSL 直接跑（`PALACE_BIN` 已持久化在 env 里）。

**Q：哪些没做 / 后续？**
A：本阶段（圆角 cell + 静电电容矩阵 + 哈密顿量）已全部完成。显式延后（均为纯增量）：端口绑定 / sidecar schema
