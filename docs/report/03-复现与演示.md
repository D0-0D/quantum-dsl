### Demo D —— 自动布线（对应汇报 §4.2）

```bash
python -c "from quantum_dsl import build; r = build('examples/cpw_route_demo.meta.yaml', 'build/demo/cpw_route', solve=False); [print(s['name'], s['length_drawn_um'], s['route_primitives']) for s in r['layout'].subsystems]"
# 预期: R1 3000.0 18 / R2 3000.0 20 / R3 3000.0 18   (原语数以实际为准; 每条 subsystems 还有 kind cpw_resonator, width_um 10, mode fixed, equiv_length_um 0)
```
打开 `build/demo/cpw_route/cpw_route_demo.gds.png`：三对 xmon，同一对几何右移三次只换环境——
**R1**（默认横平竖直）：Q1 的桨沿 +x 直出 60 µm（`lead`），横臂 → 一个圆角 → 竖臂驶入 Q2（转 90°）的桨；蛇形在横臂上，4 条腿，上侧一个小鼓包（余量 ≈ 49 µm）、下侧两条长腿（余量 ≈ 669 µm）——**腿不等长，按区域余量定**。
**R2**（`region` 是两个矩形的并集，右上角挖掉）：L 的拐角落在缝里 → 换 3 转弯骨架（Q3 桨出来立即右转下行，沿底部横行，再进 Q4 桨），蛇形腿缝上方短、下方长——**被区域挡住 → 绕路**。
**R3**（`axis: free`）：v1 的斜轴 RSR，3 条腿按矩形斜截面余量定，不再等腿。
版图每条路只有一行，例如 R2：`{template: cpw_route, name: R2, from: Q3.RO, to: Q4.RO, params: {R: 40, gap: 6, lead: 60}, length: {mode: fixed, L: 3000um}, region: [[1680, -720, 2200, 100], [1680, -720, 2500, -300]]}`。

把 R1 的 `region` 改窄让它装不下（x1 = 890 挡住 Q2.RO 口本身）：
```bash
sed 's/region: \[180, -720, 1000, 100\]/region: [180, -720, 890, 100]/' examples/cpw_route_demo.layout.yaml > build/demo/narrow.layout.yaml
sed 's/layout: cpw_route_demo.layout.yaml/layout: narrow.layout.yaml/' examples/cpw_route_demo.meta.yaml > build/demo/narrow.meta.yaml
python -c "from quantum_dsl import compile_layout; compile_layout('build/demo/narrow.meta.yaml')" 2>&1 | tail -6
# 预期: QuantumDslError: … R1 (cpw_route.geo): route: no feasible CPW path between the ports — smaller R / a larger region / a longer or shorter target / another axis (every leg count 2..S/2R was tried on every straight run):
#         1-turn path via 1 corner(s), 1362.83 um: segment #… leaves the region by … um (region [180.0, -720.0, 890.0, 100.0] inset by half the CPW width 11)
#         …  (逐骨架列原因, 最多 8 条)
```
退化一致性（正对共线时与 `cpw_meander` 逐段相同）：
```bash
python -m pytest tests/test_route.py -q -k degenerates -v
# 预期: test_cpw_route_degenerates_to_cpw_meander_when_ports_face PASSED
```
**demo 与两条测试已实测；窄区域那条按上面步骤构造。**

### Demo E —— QCQ 块本机求解（对应汇报 §4.4 / §5；~10 min，开场前跑好）

```bash
QDSL_PALACE_NP=8 python - <<'EOF'
from quantum_dsl import build
r = build("examples/chen_2025_3x3.meta.yaml", "build/demo/chen_blocks", solve=True, blocks=["H01"])
print(r["blocks"][0]["labels"]); print(open(r["blocks"][0]["results"]).read()[:600])
EOF
# 预期: ('H01', 'H01_pent', 'Q01_a', 'Q01_b', 'Q11_a', 'Q11_b')
#       results: 6×6 Maxwell (fF); hamiltonian.qubits: Q01 E_C ≈ 0.2199 GHz, H01 ≈ 0.1542, Q11 ≈ 0.2199; couplings Q01–H01 g ≈ 66 MHz
```
本机 22 核 / 15 G：网格 22 s（75 万 tets），Palace 8 rank ~570 s。指出：块只保留 6 个 component，块外的爪被删——这就是 SI §D 的「孤立 QCQ」口径。
对 SI 的 11 个电容：对地 ×1.1–1.45、互容 ×0.4–0.5（表在 [`04`](04-论文验证闭环-chen.md) §6.3）。**2026-09-13 本机实测，2026-09-18 在 c24a1 np=32 复跑 93 s，数值相同。**

### Demo F —— 十字整片上云（对应汇报 §5；远端 ~19 min + 传输）

前提：一台有 spack Palace 0.16 的 64 核 / 128 G 机（本仓用阿里云 `c24a1`，`rrs on c24a1 -w` 开机，`rrs off c24a1` 关机；按量计费）。
```bash
# 1. 本机出网格 + config (107 s, 2.39 M tets, 137 MB); 要换 d 就先 dataclasses.replace(m, airbox={**m.airbox, "top_um": 4.0}) 再 build_mesh + palace_config
python -c "from quantum_dsl import build; print(build('examples/chen_2025_cross.meta.yaml', 'build/demo/cross', solve=False)['mesh'])"
# 2. 推上去 (rsync, ~25 s), 远端跑 (mpirun 在 spack openmpi bin; 以 root 跑要 OMPI_ALLOW_RUN_AS_ROOT=1)
rr -p build/demo/cross/chen_2025_cross.msh  c24a1:/root/qdsl/cross/ ; rr -p build/demo/cross/chen_2025_cross.json c24a1:/root/qdsl/cross/
rr c24a1 'cd /root/qdsl/cross && PATH=/root/spack/opt/spack/linux-x86_64_v4/openmpi-*/bin:$PATH OMPI_ALLOW_RUN_AS_ROOT=1 OMPI_ALLOW_RUN_AS_ROOT_CONFIRM=1 \
          /root/spack/opt/spack/linux-x86_64_v4/palace-0.16.0-*/bin/palace -np 24 chen_2025_cross.json > palace.log 2>&1; tail -3 palace.log'
# 预期 (末尾): Estimated peak per-node memory usage is: … Total 28.6G ; Elapsed Time Report … Total ~1140 s
# 3. 拉回, 后处理
rr -f c24a1:/root/qdsl/cross/postpro build/demo/cross/
python - <<'EOF'
from quantum_dsl import compile_layout, load_meta
from quantum_dsl.palace import parse_capacitance
from quantum_dsl.circuit_model import solve_circuit_model, H_PLANCK
m = load_meta("examples/chen_2025_cross.meta.yaml"); lay = compile_layout(m)
labels = sorted({f.component for f in lay.faces.values() if f.role == "metal" and f.component})
cap = parse_capacitance("build/demo/cross/postpro", labels=labels)
model = solve_circuit_model(cap.labels, cap.maxwell_fF, [{"name": q["name"], "islands": q["islands"], "E_J": q["E_J"] * H_PLANCK} for q in lay.qubits])
for q in model.qubits: print(q.name, round(q.C_sigma_fF, 2), "fF  alpha", round(q.anharmonicity_MHz, 1), "MHz")
EOF
# 预期 d = 5: Q11 90.31 fF alpha -214.5 ; Q01/Q21/Q10/Q12 88.09 alpha -219.9 ; H01… 125.6 alpha -154.2
# 预期 d = 4: Q11 101.57 fF alpha -190.7   ← 实测 12 只 −192 ± 6
```
`rr` / `rrs` 是本机的远端执行工具（见 `~/.claude/machine.md`）；换成 `ssh` / `rsync` 等价。**d = 4 / 5 / 7 与 80/3 第二档均已实测，产物在 `.claude/chen-evidence/cross_*`。**
3×3 整片同法（`chen_2025_3x3.meta.yaml`，本机网格 399 s / 340 MB，远端 np=32 86 min，峰值 69 GB）。

## 4. 故障预案

| 症状 | 处置 |
|---|---|
| 同进程第二次编译版图段错误 / "Input in flex scanner failed" | merge 的 `.geo` 里定义了 `Macro`（现在会 raise）；宏一律走 `Include` 的库文件 |
| "Redefinition of function CPW" 炸掉 session | 用户宏库与 lib 重名；lib 已改 `LIB_*` 前缀；gmsh session 进程级共享，重开 Python 进程 |
| WSL 上 Palace 在 MPI_Init 挂死 | `HWLOC_COMPONENTS=-gl`（`build()` 注入；手跑自己带） |
| Palace 被 signal 9 杀且无诊断 | 内存：8.1–8.6 GB / 百万未知量估；先放大 `mesh.min_size_um`（4 → 6 内存 ÷2.7，E_C 只动 0.6%），再换大机 |
| 云机开机后 ssh 全部 reset | 公网端口漂了：`rrs fixports`（机器手册） |
| 本地会话中途死掉 | 远端 job 是 setsid 的，照跑；`rr -j c24a1` 列、`rr -l` 看日志、`rr -f` 拉产物 |
| 模板漏赋输出变量 | 会读到 NaN → raise 指出变量名（不会静默用上一实例的值） |
