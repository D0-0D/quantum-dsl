### Demo A —— 架构、调用链与绑定 key（对应汇报 §3）

**台词**：「先看整体——整条链路只有一个入口，一条命令展开成几步；这几步靠一个名字对齐。」

**操作 1（讲调用链，对照汇报 §3.2）**：指着汇报文档 §3.2 的调用链图说：整条链路只有**一个编排函数
`build_geo()`**（`geo_build.py:55`），一条命令依次做 8 步——① 解析 sidecar → ② 定几何源（手写 `.geo` 或
`cells:` 自动生成）→ ③ 开 1 个 gmsh 会话 → ④ GDS 路 → ⑤ 网格路 → ⑥ Palace 配置 →（可选）⑦ 求解+电路模型 →
（可选）⑧ 预览。**接下来 Demo B–F 就是沿这条链一段段展开**（B/C=④⑤几何与两路产物，D=⑦求解，E=⑧预览，F=测试）。
> 可补一句依赖结构（§3.3）：「一个编排者 + 一组互不调用的叶子适配器 + 共享地基 `load_geo`/命名表——所以下游
> Palace 对几何来源无感。」

**操作 2（看绑定 key）**：打开 `examples/dsl/geo/chip_layout.geo`，指给观众看这几行：
- `Physical Surface("metal::1::Q1::pad_top")` —— 金属焊盘（→ 组名 `Q1_pad_top_sfs`，Palace Terminal）
- `Physical Surface("jj::1::Q1::jj")` —— 约瑟夫森结（→ GDS layer 20，**不进静电网格**）
- `Physical Surface("ground::1::chip::gnd")` —— 接地面（→ `gnd_layer1_sfs`）

**指向**：`src/quantum_dsl/dsl/_gmsh_physical.py:44-56`（`PHYSICAL_GROUP_NAMING`，名字→规范组名的模板）。

**一句话收尾**：「不管几何来自手写 `.geo` 还是自动生成，最后都规范化成同样的组名，所以 Palace 对几何来源无感。」

### Demo D —— 真实电容求解 → 量子比特哈密顿量（对应汇报 §4.3–4.4）

**台词**：「真正跑 Palace，解出电容矩阵，再转成量子比特频率/非谐/耦合。」

> ⚠ 这步耗时 2-3 分钟，**务必开场前先跑好**（§0.3 的第三条），现场只展示结果文件。

**（开场前已在 §0.3 跑过；此处仅列出原始命令备查）**
```bash
QDSL_RUN_PALACE=1 PYTHONPATH=src python -m quantum_dsl.dsl.geo_build \
    tests/fixtures/two_pads.meta.yaml --out-dir build/report_two_pads --run-palace
```

**操作 1**：展示 sidecar `tests/fixtures/two_pads.meta.yaml` 末尾的 `circuit_model:` 块
（两个单岛 transmon，`L_J=10nH`）。

**操作 2**：展示结果文件，指三块：

```bash
cat build/report_two_pads/chip.results.yaml
```

- **电容矩阵（Maxwell，本次实测，fF）**：`[[24.73, -1.98], [-1.98, 24.73]]`
  —— 对角 +、非对角 −、对称（物理正确）。
- **哈密顿量（tier 2，本次实测）**：每比特 `f01 ≈ 9.365 GHz`、`E_C ≈ 0.788 GHz`、`α ≈ -788 MHz`、`E_J/E_C ≈ 20.7`。
- **耦合**：`C_g = 1.976 fF`、`g = 374 MHz`。
- 还可指 `provenance:` 里 geo/mesh/config 的 SHA-256（陈旧检测）。

**一句话（应对追问）**：「`E_C` 不是直接取 Maxwell 对角，而是取量子比特岛子矩阵**求逆**——N≥3 时天真对角会漂移，逆电容法严格正确。」

### Demo E —— GDSFactory 可视化（对应汇报 §4.5）

**台词**：「版图可以用 GDSFactory 打开看。」

**弹出 GDSFactory 交互窗口**（把 `chip.gds` 经 `gf.import_gds` 接入 gdsfactory 再绘制）。
**注意命令开头的 `QT_QPA_PLATFORM=xcb` 不能省**——WSLg 下 Qt 默认找 wayland 插件（缺失），不强制走 xcb 时 `plt.show()`
会崩在 `Could not find the Qt platform plugin "wayland"`：
```bash
QT_QPA_PLATFORM=xcb PYTHONPATH=src python - build/report_chip_layout/chip.gds <<'PY'
import sys, matplotlib
matplotlib.use("QtAgg")
import matplotlib.pyplot as plt
from quantum_dsl.dsl.gds_viz import to_gdsfactory_component
c = to_gdsfactory_component(sys.argv[1])   # = gf.import_gds(...)，GDSFactory 桥
print("gdsfactory Component:", c.name)
c.plot()                                    # gdsfactory 自己的 matplotlib 渲染
plt.show(block=True)                         # 必须 block=True！见下方说明
PY
```
> 两个**不能省**的点：(1) 开头 `QT_QPA_PLATFORM=xcb`——否则 Qt 找 wayland 插件失败；(2) `plt.show(block=True)`——
> gdsfactory 导入后 matplotlib 处于**交互模式**，裸 `plt.show()` 不阻塞、窗口会**一闪而过**，必须显式 `block=True`。
> 若已在本 shell 跑过 §0.1 的 `export QT_QPA_PLATFORM=xcb`，命令开头那段可省；写上是为了**单条粘贴也能跑**。

**或直接看预览 PNG**（开场前 `--png` 已生成）：
```bash
xdg-open build/report_chip_layout/chip.png      # 若无 xdg-open，可换 eog build/report_chip_layout/chip.png
```

**指向**：图里蓝色是接地面（layer 1）、中间横向白缝是 CPW 总线被挖出的 gap、上方两个橙色短线是 JJ（layer 20）。
参考图：`docs/report/img/chip_layout_gds.png`。

**一句话**：「`gds_viz` 只读成品 GDS、纯附加；装了 gdsfactory 就自动用它（`backend=gdsfactory`），没装就回退 matplotlib。」

## 5. 故障预案

| 现象 | 处理 |
|---|---|
| `conda: command not found` | 先 `source ~/miniconda3/etc/profile.d/conda.sh`，再 `conda activate metal-env` |
| `ModuleNotFoundError: quantum_dsl` | 忘了 `export PYTHONPATH=src`（或每条命令前加 `PYTHONPATH=src`） |
| GUI 窗口不弹 | 确认 `echo $DISPLAY` 非空；`export QT_QPA_PLATFORM=xcb` |
| Palace 求解很慢/卡住 | 正常需 2-3 分钟；**务必开场前预跑** §0.3 第三条，现场只展示结果文件 |
| Palace 报缺二进制 | 确认 `echo $PALACE_BIN` 指向 spack palace 0.16；`run_palace` 会自动用它 |
| 想重置某个产物 | `rm -rf build/report_<stem>` 后重跑对应 `geo_build` 命令（产物全在 out-dir，删了不影响源码） |
